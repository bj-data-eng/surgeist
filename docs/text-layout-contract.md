# Text preparation, selected lines and renderer admission

This is the normative implementation contract selected for [#1080](https://github.com/bj-data-eng/surgeist/issues/1080), [#1082](https://github.com/bj-data-eng/surgeist/issues/1082), [#72](https://github.com/bj-data-eng/surgeist/issues/72) and [#73](https://github.com/bj-data-eng/surgeist/issues/73). It assigns behavior to the existing text, layout, render and root owners; it introduces no crate or interchangeable provider protocol. It does not settle the separate CSS feature issues or claim that Parley implements those standards. The implementation must preserve the currently supported text API behavior while replacing its Parley intermediary.

## Evidence and authority

Root owns this cross-crate contract. It applies when implementing the linked text/layout/render contributions and their adapters. Current source remains authoritative for implemented behavior; this document specifies the selected replacement. A change to an observable rule requires an explicit replacement determination in this document and the affected issue, not an implementation-local exception. Completion requires the consumer-specific evidence below; until then, these decisions do not assert feature support.

The inspected repository basis is `3c412118b5e9f4ad8a34a1331f8c500618599498`. Current code builds and independently wraps a Parley layout in [system.rs](https://github.com/bj-data-eng/surgeist/blob/3c412118b5e9f4ad8a34a1331f8c500618599498/crates/surgeist-text/src/system.rs#L130), projects already placed lines in [layout.rs](https://github.com/bj-data-eng/surgeist/blob/3c412118b5e9f4ad8a34a1331f8c500618599498/crates/surgeist-text/src/layout.rs#L86), and represents cluster interaction rectangles using advance and line height at [line 239](https://github.com/bj-data-eng/surgeist/blob/3c412118b5e9f4ad8a34a1331f8c500618599498/crates/surgeist-text/src/layout.rs#L239). These facts establish the replacement surface; they are not the future contract.

The retained Parley source witness is [Parley 0.9 text contract witness](../references/parley-0.9-text-contract-witness.md). It records the registry checksum, exact file hashes, excerpts and license. Parley 0.9 stores normalized coordinates and synthesis separately from its font blob, and shapes with Harfrust. Its builder also performs analysis, resolution and shaping before the line breaker. The changes below are design decisions required to join those owners correctly, not claims that the current code already supports the join.

## Owners

| Owner | Required responsibility |
| --- | --- |
| Text | Authored/processed mappings; Unicode analysis; font matching/fallback; shaping; opportunities and replacement alternatives; line-edge text processing; selected-line shaping and spacing; line bidi ordering including atomic participants; font/glyph outline metrics; cursor, selection, hit and accessibility projections from finalized geometry. |
| Layout | Box and float constraints, intrinsic box aggregation, available spans, actual break choice, spacing allocation, line/fragment placement, baselines and atomic box geometry. |
| Render | Safe font-resource admission; executing the effective font instance; selecting and validating the glyph representation used by the backend; its local ink bounds; rasterization. |
| Root | Every text/layout/render conversion and association; one composed ordering; off-side validation and coherent publication of geometry, paint and interaction results. |

Move the supplied-level bidi reorder and applicable line-edge text operations out of layout when their callers use text. Keep line fitting, floats, intrinsic box aggregation and physical placement in layout. Include atomic inline participants and directional boundary controls in the ordering input: reordering text-only runs cannot establish the order of a mixed line. Fixture font-width heuristics do not become production algorithms.

## Concrete text values and lifetime

Expose concrete owned values in `surgeist-text`, with private validated fields and ordinary constructors/accessors. The names here define roles; implementation may align names with the existing API without adding equivalent parallel models.

`PreparedText` owns immutable authored text, validated style/inline source facts, processed text, Unicode analysis, logical units, break alternatives and a captured font catalogue. Each unit retains authored UTF-8 ranges and processed UTF-8 ranges. Removed/collapsed content retains zero-extent source anchors with affinity; expansions retain their many-to-many source association. A presentation-only replacement, including a selected hyphen, retains an insertion anchor and does not invent authored characters. Plaintext projection reads the authored/source mapping and its own required trim/collapse rules, not emitted glyph strings.

A preparation has an opaque owner-issued identity. Clones retain the same identity; independently prepared equal strings do not gain interchangeable unit handles. An internally shared allocation token with identity comparison is sufficient: do not hash content into a supposedly unique public identity. Source ID/revision and font generation are observable provenance, not substitutes for this identity. Use `usize` for source/unit indices and checked arithmetic; do not inherit Parley's compressed `u8`/`u16` text length/offset fields as public limits.

`PreparedText` retains strong ownership of every font resource it uses. A face consists of immutable font bytes, collection index and text-owned resource identity. An `EffectiveFontInstance` additionally carries the resolved normalized coordinates for every variation axis, the actual shaping size and concrete synthesis parameters. Coordinates are the actual canonical values passed to shaping/metrics, not merely authored variation settings. Synthetic skew and emboldening must have concrete executable values, not an unconsumed suggestion. The synthesis resolver records its executable skew transform and emboldening displacement once for both text geometry and render admission. Fontique’s boolean faux-bold suggestion alone is insufficient; an unresolved suggestion is a typed unsupported-instance error, never silently ignored. The applicable font-synthesis feature issue owns which synthesis is requested/permitted; #1080/#1082 own converting the selected result to these concrete executable parameters.

Font catalogue changes publish a new immutable catalogue identity and invalidate preparation cache lookup for new requests. Existing preparations retain their old fonts and remain valid for reading/finalization. Root rejects joining them into a newly captured composed result whose source/style/font identities differ. A numeric generation counter must fail on exhaustion rather than saturate and reuse an identity. The current refresh method only advances a counter; the replacement must actually publish the refreshed/registered catalogue. Provide concrete safe font registration and a `RegisteredOnly` catalogue mode for reproducible tests; preserve the default system catalogue behavior. This is not a font-provider trait.

## Selected-line protocol

1. `System::prepare` validates source/styles, resolves fonts, analyzes text and returns `PreparedText`. It does not choose the composed paragraph's line breaks. Its preliminary measurements/opportunities are explicitly preliminary wherever selected boundaries can change shaping or line-edge processing.
2. Root lowers text units, opportunities and metrics to layout's validated inline inputs. Layout chooses a candidate logical range, break alternative and float-dependent span. It supplies the complete logical participant sequence, including atomic inline identities and directional controls, plus the relevant line context.
3. `PreparedText` validates a selection and creates `SelectedLine`. Private handles bind the selection to that preparation; validate range order, unit boundaries, break legality, selected replacement, atomic participant uniqueness and context. Selection context includes writing mode/orientation, start/end and forced/soft break facts, tab origin, available text span, indentation/hanging facts and exact spacing allocations. Do not pass unrelated paint policy into shaping.
4. Text finalizes that selection. `FinalizedLine` owns its selected preparation, the applied replacement and processed mapping, final effective font runs/glyphs, actual advances, line-edge/hanging facts, text metrics and outline ink, visual order including atomic placeholders, and caret/selection anchors. It returns line-local geometry. It never chooses a different break or places a box. Finalization applies the selected line's shaping boundaries, bidi line rules and text spacing to one result shared by all consumers.
5. Layout evaluates the returned metrics against its candidate span, including changes to float intersection caused by actual line height. It can choose another candidate/context and finalize again. After choosing a fitting line it supplies its space allocation and obtains the final geometry; it rechecks any resulting width/height feedback before committing. Preliminary metrics are never silently treated as final.
6. Root supplies validated placement of those exact finalized lines, including line/fragment IDs, physical origin, writing-mode basis, baseline and atomic box rectangles, to text's placed-layout constructor. The constructor validates identities, completeness and geometry before returning a placed `Layout`. Painting, hit testing, movement, selection and accessibility consume this placed result. They cannot call a separate paragraph wrapper to recreate it.

Finalization is deterministic for a preparation and complete selection context. Layout's feedback algorithm visits its finite candidate/context states until it selects a valid state or returns its existing no-fit outcome; revisiting a complete already-rejected candidate/context state is a typed feedback-cycle error (or the formatter’s explicit no-fit failure), even when feedback is identical and even for a cycle through multiple states. A stable fitting state commits; rejected states cannot be retried without a changed input. Do not introduce a magic maximum pass count. Layout must ensure progress in its own float/box algorithm. A no-fit line allowed by applicable overflow semantics remains a deliberate layout outcome, not a text finalizer fallback.

The standalone `System::layout` convenience path retains the currently supported wrapping/alignment behavior by choosing lines through the same preparation/finalization machinery. Its simple paragraph chooser is private to text; root's CSS formatter does not use it as a second formatter. Unsupported style combinations remain explicit errors until the owning standards issue implements them.

## Numbers, errors and publication

Shared logical geometry uses finite `f64` values. Provider font sizes and shaping glyph geometry remain canonical `f32` where the providers require that precision. Text reports actual canonical glyph positions and advances; widening those values to `f64` is exact. Root converts to the selected layout scalar at named boundaries: an `f32` layout rounds once, then returns its actual rounded allocation/context to finalization; an `f64` layout retains its values until the provider boundary. Finalizer converts provider-required spacing/positions once using IEEE round-to-nearest, ties-to-even and returns the actual result for fit/placement. No layer uses the unrounded requested value as if it were emitted geometry. Do not infer success from an unchecked `as` cast.

Validate every conversion for finite output and value category: a positive size/extent cannot become zero, negative, infinity or NaN; a nonzero signed offset cannot silently become zero. Negative finite glyph advances and coordinates remain valid where the current contracts allow them. Preserve large physical origins in render's `f64` transform instead of adding them to local `f32` glyph coordinates. No infinity sentinel represents an unconstrained width; use the existing optional constraint. Bounds are computed from the admitted canonical geometry and transformed in their supported precision.

Use typed errors for invalid source/style, invalid selection/break/replacement, wrong preparation or fragment identity, mismatched captured source/style/font catalogue, numeric conversion with phase/value/category, font/provider admission, unsupported capability and feedback cycle. Check narrowing needed by a provider's actual index API and report its representability limit; impose no unrelated text length cap. Malformed external fonts/ranges cannot reach an `unwrap`, assertion or overflow panic. Error payloads must not expose Parley types or backend-named reasons. Extend the existing error model rather than adding compatibility wrappers.

Each operation builds and validates a complete result before publishing it. An error publishes no partial placed layout, source mapping, scene batch or accessibility update. Successful memoization of immutable intermediate values is allowed, but cannot change observable font/source state after a failed request. Root builds paint and interaction/accessibility outputs off-side from one captured result and publishes only after all required joins/admissions succeed. A render failure cannot leave glyphs from one preparation paired with interaction from another.

## Renderer admission and ink

#1082 includes the necessary render-owned extension: a concrete headless glyph-preparation operation accepts the face, effective instance and canonical local glyph geometry; validates font/glyph resources; selects the same outline/COLR/bitmap representation used by drawing; and returns an admitted immutable glyph run with local `Ink` or proven `Empty` bounds. Drawing consumes this result, including its normalized coordinates and synthesis, rather than reselecting a representation or using empty coordinates. No new adapter trait is required.

Render owns resource/instance identity within that admitted result and keeps bytes alive through scene execution. Root maps the captured text face/instance to admitted render resources without collision-prone content hashes or caller-supplied IDs masquerading as admission. A changed face/axis/size/synthesis value cannot reuse an incompatible prepared glyph run. Safe invalid-font, out-of-range-glyph and unsupported-representation errors occur before scene publication. Bounds must cover the admitted representation, including bearings, overhang, marks, variation and synthesis; a conservative representation-derived bound is valid, an advance rectangle is not. If the renderer cannot establish a required graph bound for a representation, it rejects that graph admission with a typed capability error. An unsupported device operation is not silently rendered as a different font instance.

Text owns font/glyph outline metrics needed for layout and decorations. It also exposes resolved font metrics without requiring a glyph run, so an empty decorating fragment can query its associated decorating-box font at that box’s computed size and effective variation coordinates. Strikeout position is a center offset positive above the alphabetic baseline. Use valid same-instance font strikeout metrics. Skrifa’s decoration offset is top-defined; normalize its offset to the owned center convention by subtracting half its reported thickness. If the provider decoration is absent or has a nonfinite offset/thickness or nonpositive thickness, use center offset half the resolved ascent and thickness computed size divided by 18 in scaled logical units. Reject invalid ascent/size rather than creating an invalid fallback. These are explicit Surgeist fallbacks, not empty-set averages or a CSS-mandated formula. Place a horizontal decoration with center `baseline - offset`, then subtract half the used thickness for its top edge. Writing-mode conversion occurs at the placement boundary. The Parley witness retains the upstream ascent/2 fallback and raw units-per-em/18 expression; the replacement deliberately scales the fallback thickness and does not copy that raw value. Render's admitted representation bounds establish graph paint ink and may differ for color/bitmap glyphs. Neither replaces advance/line boxes, clip, overflow or interaction geometry. Preserve `Unspecified` only for direct render paths that already support it; graph commands require admitted `Ink`/`Empty`. Do not require GPU access for font/instance admission or bound calculation. Backend-local preparation and rasterization remain in render; root owns the cross-crate lowering and paint association.

Accessibility remains an optional text-owned projection from the committed placed layout. Its state binds node/grapheme handles to that layout identity, retains source ranges and rejects mismatched joins. Host parent/focus identity remains supplied by the caller. Cursor/selection/hit APIs use the same source affinity and finalized visual order, independent of paint ink.

Before removing Parley, implementation must verify the private extraction call closure, characterize the standalone supported API against deterministic expectations, and establish the renderer's exact synthesis/color/bitmap bounds execution for the chosen backend. Those are finite implementation checks inside #1080/#1082, not unresolved owner/protocol decisions or blanket prerequisite gates.
