# Corpus operations

Complete [getting started](getting-started.md) first. Mutation procedures require
Apple-Silicon macOS and caller-owned corpus declarations and inputs.

## Import and generate a CSS corpus

Use an existing clean CSSTree checkout at the corpus manifest's exact pin and the
local workspace `surgeist-css-generate` target enabled by `css-corpus`.
The manifest owns source pins, expected file/case counts, import and expectation
roots, and the report path. From the Surgeist product root, set `CORPUS_OWNER`,
`CORPUS_ROOT`, and `CSSTREE_SOURCE` to the existing absolute paths for your
operation; the corpus root must be contained by its owner:

```sh
cargo run --offline --locked -p surgeist-generator --features css-corpus --bin surgeist-css-generate -- --owner-root "$CORPUS_OWNER" --corpus-root "$CORPUS_ROOT" import-csstree --source-root "$CSSTREE_SOURCE"
cargo run --offline --locked -p surgeist-generator --features css-corpus --bin surgeist-css-generate -- --owner-root "$CORPUS_OWNER" --corpus-root "$CORPUS_ROOT" generate
cargo run --offline --locked -p surgeist-generator --features css-corpus --bin surgeist-css-generate -- --owner-root "$CORPUS_OWNER" --corpus-root "$CORPUS_ROOT" check-corpus
```

Import verifies the checkout and writes its canonical sidecar; it does not
acquire or execute CSSTree. A successful check verifies persisted source
attestation, neutral expectations, and reports from the corpus root alone.

For a selected fixture, use `generate --filter <fixture>` with the same roots.
Filtered generation updates matching expectations already owned by the historical
full report and preserves the report and other expectations. Run full generation
before expecting a current full-corpus check to pass after changed outputs.

## Import an explicit WPT bundle

Prepare a reviewed WPT manifest using the [reference schema](reference.md#wpt-manifest-and-receipt).
Choose a full immutable commit and an explicit file allowlist, including each
file's applicable license material. During separately authorized acquisition,
retrieve each path from
`https://raw.githubusercontent.com/web-platform-tests/wpt/<revision>/<path>`
and bind its SHA-256 to that exact URL in the acquisition record. A local digest
alone does not establish which upstream commit supplied the bytes.

Keep this existing bundle under the caller's owner-local
`tmp/surgeist-sources/wpt/<revision>/` directory, outside corpus output and
coordination roots. Preserve upstream relative paths and bytes. A full checkout,
browser, Node installation, and JavaScript execution are unnecessary. The
manifest, acquisition record, preserved source/license inventory, and adaptation
vectors belong to the consuming corpus.

From the Surgeist root, set `CORPUS_OWNER`, `CORPUS_ROOT`, and `WPT_SOURCE_BUNDLE`
to existing absolute paths, then run the selected commands serially:

```sh
cargo run --offline --locked -j 1 -p surgeist-generator --no-default-features --features css-corpus --bin surgeist-css-generate -- --owner-root "$CORPUS_OWNER" --corpus-root "$CORPUS_ROOT" import-wpt --source-root "$WPT_SOURCE_BUNDLE"
cargo run --offline --locked -j 1 -p surgeist-generator --no-default-features --features css-corpus --bin surgeist-css-generate -- --owner-root "$CORPUS_OWNER" --corpus-root "$CORPUS_ROOT" check-corpus
```

Import verifies the file/license hashes and publishes their exact bytes together
with a canonical receipt. It does not fetch or execute source. Checking remains
offline after the bundle is removed and verifies that imported inventory and
receipt. Run the consuming CSS corpus's separate binding and behavioral tests
for grammar, construction, normalization, and serialization evidence. WPT
`generate` is unsupported and returns an error before publication.

To update a selection, acquire and review the replacement declarations and
bundle, then import again. The prior receipt must still account for every
existing output byte; import rejects unknown or tampered output instead of
deleting it. A valid replacement removes only obsolete files owned by that
prior receipt. Source/license verification failures leave existing output intact.

## Integrate a browser host

Enable `browser-corpus` and supply an existing browser and checked corpus, case,
browser, and report declarations.

1. Implement `BrowserCorpusAdapter` with an associated error type. `prepare`
   consumes captured fixture/global inputs and returns a document, readiness
   expression, ordered setup, measurement expression, and resource dependencies.
   `lower` consumes opaque JSON and returns generated bytes or unsupported
   outcomes for the declared cases. Both callbacks are synchronous.
2. Call `browser::run_supervisor_from_env` before parsing the host's own
   arguments. Handle a present supervisor result without falling through to
   ordinary argument parsing. Authenticated invocation is independent of the
   host filename and never calls the adapter in the supervisor process.
3. Call `browser::generate` with an existing browser path and owned adapter.
   Adapter errors preserve their original source and fixture/phase association.
4. Use `browser::check_corpus` to verify the resulting full corpus offline.
   Checking prepares current inputs to validate complete linked resources; it
   does not launch a browser. A diagnostic or stale report cannot pass.

Consult the [public browser module](../src/browser/mod.rs) and
[models](../src/browser/model.rs) for exact signatures and checked constructors.

## Acquire and attest browser inputs

Use explicit `acquire_source` and `acquire_browser` operations only when
acquisition is intended and authorized. Existing-only mode verifies cached
inputs without fetching or installing. Keep caches under their declared owner
and outside corpus outputs and recovery directories.

Use `SourceImportSpec` to declare the repository/revision, source tree,
exclusions, expected count, and preserved authored files. `import_source`
verifies the checkout and atomically publishes imported bytes and attestation.
Import can adopt matching existing bytes after verification before attestation.
`verify_import` checks persisted imported bytes and their pin offline;
`verify_source_import` checks the existing pinned checkout as well. Ordinary
corpus checks validate persisted attestations offline without the checkout.
See [source import APIs](../src/browser/source_import.rs) for operation contracts.

## Migrate from 0.1

Version 0.2 removes `layout-browser`, `surgeist_generator::layout`, and this
crate's `surgeist-layout-generate` executable. Layout users invoke the thin
binary in `surgeist-layout`, which enables `browser-corpus` and supplies its
private measurement/lowering adapter. Other callers supply their own adapter.
This crate contains no layout XML schema or browser helper protocol.

For a legacy browser report, supply checked `PriorOwnership` for one full
migration. Paths and hashes are independently verified through publication;
legacy ownership cannot authorize filtered migration or current-report checking.
See [publication and recovery](explanation.md) before interpreting diagnostic or
filtered output state.
