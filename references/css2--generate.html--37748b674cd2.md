# 12 Generated content, automatic numbering, and lists

(hide)

<strong>Note:</strong> Several sections of this specification have been updated by other specifications. Please, see ["Cascading Style Sheets (CSS) — The Official Definition"](https://www.w3.org/TR/CSS/#css) in the latest CSS Snapshot for a list of specifications and the sections they replace.

The CSS Working Group is also developing [CSS level 2 revision 2 (CSS 2.2).](https://www.w3.org/TR/CSS22/)

In some cases, authors may want user agents to render content that does not come from the [document tree](css2--conform.html--de58593b67d7.md#doctree). One familiar example of this is a numbered list; the author does not want to list the numbers explicitly, he or she wants the user agent to generate them automatically. Similarly, authors may want the user agent to insert the word "Figure" before the caption of a figure, or "Chapter 7" before the seventh chapter title. For audio or braille in particular, user agents should be able to insert these strings.

In CSS 2.1, content may be generated by two mechanisms:

- The ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property, in conjunction with the :before and :after pseudo-elements.
- Elements with a value of 'list-item' for the ['display'](css2--visuren.html--3f334c530cf4.md#propdef-display) property.

## 12.1 The :before and :after pseudo-elements

Authors specify the style and location of generated content with the :before and :after pseudo-elements. As their names indicate, the :before and :after pseudo-elements specify the location of content before and after an element's [document tree](css2--conform.html--de58593b67d7.md#doctree) content. The ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property, in conjunction with these pseudo-elements, specifies what is inserted.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, the following rule inserts the string "Note: " before the content of every P element whose "class" attribute has the value "note":
>
> ```text
> 
> p.note:before { content: "Note: " }
> ```
The formatting objects (e.g., boxes) generated by an element include generated content. So, for example, changing the above style sheet to:

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> p.note:before { content: "Note: " }
> p.note        { border: solid green }
> ```
would cause a solid green border to be rendered around the entire paragraph, including the initial string.

The :before and :after pseudo-elements [inherit](css2--cascade.html--c7aff33e6f0d.md#inheritance) any inheritable properties from the element in the document tree to which they are attached.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, the following rules insert an open quote mark before every Q element. The color of the quote mark will be red, but the font will be the same as the font of the rest of the Q element:
>
> ```text
> 
> q:before {
>   content: open-quote;
>   color: red
> }
> ```
In a :before or :after pseudo-element declaration, non-inherited properties take their [initial values](css2--about.html--c67ff594c990.md#initial-value).

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> So, for example, because the initial value of the ['display'](css2--visuren.html--3f334c530cf4.md#propdef-display) property is 'inline', the quote in the previous example is inserted as an inline box (i.e., on the same line as the element's initial text content). The next example explicitly sets the ['display'](css2--visuren.html--3f334c530cf4.md#propdef-display) property to 'block', so that the inserted text becomes a block:
>
> ```text
> 
> body:after {
>     content: "The End";
>     display: block;
>     margin-top: 2em;
>     text-align: center;
> }
> ```
The :before and :after pseudo-elements interact with other boxes as if they were real elements inserted just inside their associated element.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, the following document fragment and style sheet:
>
> ```text
> 
> <p> Text </p>                   p:before { display: block; content: 'Some'; }
> ```
>
> ...would render in exactly the same way as the following document fragment and style sheet:
>
> ```text
> 
> <p><span>Some</span> Text </p>  span { display: block }
> ```
>
> Similarly, the following document fragment and style sheet:
>
> ```text
> 
> <h2> Header </h2>     h2:after { display: block; content: 'Thing'; }
> ```
>
> ...would render in exactly the same way as the following document fragment and style sheet:
>
> ```text
> 
> <h2> Header <span>Thing</span></h2>   h2 { display: block; }
>                                       span { display: block; }
> ```
> <strong data-conversion-semantic="note">Note</strong>
>
> <strong>Note.</strong> This specification does not fully define the interaction of :before and :after with replaced elements (such as IMG in HTML). This will be defined in more detail in a future specification.

This property is used with the :before and :after pseudo-elements to generate content in a document. Values have the following meanings:

<a id="x9"></a>

<strong>none</strong>

The pseudo-element is not generated.

<a id="x10"></a>

<strong>normal</strong>

Computes to 'none' for the :before and :after pseudo-elements.

<a id="x11"></a>

[<strong>&lt;string&gt;</strong>](css2--syndata.html--02e71c159e14.md#value-def-string)

Text content (see the section on [strings](css2--syndata.html--02e71c159e14.md#strings)).

<a id="x12"></a>

[<strong>&lt;uri&gt;</strong>](css2--syndata.html--02e71c159e14.md#value-def-uri)

The value is a URI that designates an external resource (such as an image). If the user agent cannot display the resource it must either leave it out as if it were not specified or display some indication that the resource cannot be displayed.

<a id="x13"></a>

[<strong>&lt;counter&gt;</strong>](css2--syndata.html--02e71c159e14.md#value-def-counter)

[Counters](css2--syndata.html--02e71c159e14.md#counter) may be specified with two different functions: 'counter()' or 'counters()'. The former has two forms: 'counter(<var>name</var>)' or 'counter(<var>name</var>, <var>style</var>)'. The generated text is the value of the innermost counter of the given name in scope at this pseudo-element; it is formatted in the indicated [style](#counter-styles) ('decimal' by default). The latter function also has two forms: 'counters(<var>name</var>, <var>string</var>)' or 'counters(<var>name</var>, <var>string</var>, <var>style</var>)'. The generated text is the value of all counters with the given name in scope at this pseudo-element, from outermost to innermost separated by the specified string. The counters are rendered in the indicated [style](#counter-styles) ('decimal' by default). See the section on [automatic counters and numbering](#counters) for more information. The name must not be 'none', 'inherit' or 'initial'. Such a name causes the declaration to be ignored.

<a id="x15"></a>

<a id="x14"></a>

[<strong>open-quote</strong>](css2--generate.html--37748b674cd2.md#value-def-open-quote) and [<strong>close-quote</strong>](css2--generate.html--37748b674cd2.md#value-def-close-quote)

These values are replaced by the appropriate string from the [<strong>'quotes'</strong>](css2--generate.html--37748b674cd2.md#propdef-quotes) property.

<a id="x17"></a>

<a id="x16"></a>

[<strong>no-open-quote</strong>](css2--generate.html--37748b674cd2.md#value-def-no-open-quote) and [<strong>no-close-quote</strong>](css2--generate.html--37748b674cd2.md#value-def-no-close-quote)

Introduces no content, but increments (decrements) the level of nesting for quotes.

<a id="x18"></a>

<strong>attr(X)</strong>

This function returns as a string the value of attribute X for the subject of the selector. The string is not parsed by the CSS processor. If the subject of the selector does not have an attribute X, an empty string is returned. The case-sensitivity of attribute names depends on the document language.

> <strong data-conversion-semantic="note">Note</strong>
>
> <strong>Note.</strong> In CSS 2.1, it is not possible to refer to attribute values for other elements than the subject of the selector.

The ['display'](css2--visuren.html--3f334c530cf4.md#propdef-display) property controls whether the content is placed in a block or inline box.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> The following rule causes the string "Chapter: " to be generated before each H1 element:
>
> ```text
> 
> H1:before { 
>   content: "Chapter: ";
>   display: inline;
> }
> ```
Authors may include newlines in the generated content by writing the "&#x5C;A" escape sequence in one of the strings after the ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property. This inserted line break is still subject to the ['white-space'](css2--text.html--467a8857ae69.md#propdef-white-space) property. See ["Strings"](css2--syndata.html--02e71c159e14.md#strings) and ["Characters and case"](css2--syndata.html--02e71c159e14.md#escaped-characters) for more information on the "&#x5C;A" escape sequence.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> ```text
> 
> h1:before {
>     display: block;
>     text-align: center;
>     white-space: pre;
>     content: "chapter\A hoofdstuk\A chapitre"
> }
> ```
Generated content does not alter the document tree. In particular, it is not fed back to the document language processor (e.g., for reparsing).

## 12.3 Quotation marks

In CSS 2.1, authors may specify, in a style-sensitive and context-dependent manner, how user agents should render quotation marks. The ['quotes'](css2--generate.html--37748b674cd2.md#propdef-quotes) property specifies pairs of quotation marks for each level of embedded quotation. The ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property gives access to those quotation marks and causes them to be inserted before and after a quotation.

<a id="quotes-specify"></a>

### 12.3.2 Inserting quotes with the ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property

<a id="value-def-open-quote"></a>

<a id="value-def-close-quote"></a>

Quotation marks are inserted in appropriate places in a document with the 'open-quote' and 'close-quote' values of the ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property. Each occurrence of 'open-quote' or 'close-quote' is replaced by one of the strings from the value of ['quotes'](css2--generate.html--37748b674cd2.md#propdef-quotes), based on the depth of nesting.

'Open-quote' refers to the first of a pair of quotes, 'close-quote' refers to the second. Which pair of quotes is used depends on the nesting level of quotes: the number of occurrences of 'open-quote' in all generated text before the current occurrence, minus the number of occurrences of 'close-quote'. If the depth is 0, the first pair is used, if the depth is 1, the second pair is used, etc. If the depth is greater than the number of pairs, the last pair is repeated. A 'close-quote' or 'no-close-quote' that would make the depth negative is in error and is ignored (at rendering time): the depth stays at 0 and no quote mark is rendered (although the rest of the 'content' property's value is still inserted).

> <strong data-conversion-semantic="note">Note</strong>
>
> <em><strong>Note.</strong> The quoting depth is independent of the nesting
of the source document or the formatting structure.</em>

<a id="value-def-no-close-quote"></a>

Some typographic styles require open quotation marks to be repeated before every paragraph of a quote spanning several paragraphs, but only the last paragraph ends with a closing quotation mark. In CSS, this can be achieved by inserting "phantom" closing quotes. The keyword 'no-close-quote' decrements the quoting level, but does not insert a quotation mark.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> The following style sheet puts opening quotation marks on every paragraph in a BLOCKQUOTE, and inserts a single closing quote at the end:
>
> ```text
> 
> blockquote p:before     { content: open-quote }
> blockquote p:after      { content: no-close-quote }
> blockquote p.last:after { content: close-quote }
> ```
>
> This relies on the last paragraph being marked with a class "last".

<a id="value-def-no-open-quote"></a>

For symmetry, there is also a 'no-open-quote' keyword, which inserts nothing, but increments the quotation depth by one.

## 12.4 Automatic counters and numbering

Automatic numbering in CSS 2.1 is controlled with two properties, ['counter-increment'](css2--generate.html--37748b674cd2.md#propdef-counter-increment) and ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset). The counters defined by these properties are used with the counter() and counters() functions of the the ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property.

| <em>Percentages:</em>   | N/A                                                                                                                                                                                                                                                                                                   |

The ['counter-increment'](css2--generate.html--37748b674cd2.md#propdef-counter-increment) property accepts one or more names of counters (identifiers), each one optionally followed by an integer. The integer indicates by how much the counter is incremented for every occurrence of the element. The default increment is 1. Zero and negative integers are allowed.

The ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset) property also contains a list of one or more names of counters, each one optionally followed by an integer. The integer gives the value that the counter is set to on each occurrence of the element. The default is 0.

The keywords 'none', 'inherit' and 'initial' must not be used as counter names. A value of 'none' on its own means no counters are reset, resp. incremented. 'Inherit' on its own has its usual meaning (see [6.2.1](css2--cascade.html--c7aff33e6f0d.md#value-def-inherit)). 'Initial' is reserved for future use.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> This example shows a way to number chapters and sections with "Chapter 1", "1.1", "1.2", etc.
>
> ```text
> 
> BODY {
>     counter-reset: chapter;      /* Create a chapter counter scope */
> }
> H1:before {
>     content: "Chapter " counter(chapter) ". ";
>     counter-increment: chapter;  /* Add 1 to chapter */
> }
> H1 {
>     counter-reset: section;      /* Set section to 0 */
> }
> H2:before {
>     content: counter(chapter) "." counter(section) " ";
>     counter-increment: section;
> }
> ```
If an element increments/resets a counter and also uses it (in the ['content'](css2--generate.html--37748b674cd2.md#propdef-content) property of its :before or :after pseudo-element), the counter is used <em>after</em> being incremented/reset.

If an element both resets and increments a counter, the counter is reset first and then incremented.

If the same counter is specified more than once in the value of the ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset) and ['counter-increment'](css2--generate.html--37748b674cd2.md#propdef-counter-increment) properties, each reset/increment of the counter is processed in the order specified.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> The following example will reset the 'section' counter to 0:
>
> ```text
> 
> H1 { counter-reset: section 2 section }
> ```
>
> The following example will increment the 'chapter' counter by 3:
>
> ```text
> 
> H1 { counter-increment: chapter chapter 2 }
> ```
The ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset) property follows the cascading rules. Thus, due to cascading, the following style sheet:

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> H1 { counter-reset: section -1 }
> H1 { counter-reset: imagenum 99 }
> ```
will only reset 'imagenum'. To reset both counters, they have to be specified together:

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> H1 { counter-reset: section -1 imagenum 99 }
> ```
<a id="scope"></a>

### 12.4.1 Nested counters and scope

Counters are "self-nesting", in the sense that resetting a counter in a descendant element or pseudo-element automatically creates a new instance of the counter. This is important for situations like lists in HTML, where elements can be nested inside themselves to arbitrary depth. It would be impossible to define uniquely named counters for each level.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> Thus, the following suffices to number nested list items. The result is very similar to that of setting 'display:list-item' and 'list-style: inside' on the LI element:
>
> ```text
> 
> OL { counter-reset: item }
> LI { display: block }
> LI:before { content: counter(item) ". "; counter-increment: item }
> ```
<a id="x29"></a>

The scope of a counter starts at the first element in the document that has a ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset) for that counter and includes the element's descendants and its following siblings with their descendants. However, it does not include any elements in the scope of a counter with the same name created by a 'counter-reset' on a later sibling of the element or by a later 'counter-reset' on the same element.

If ['counter-increment'](css2--generate.html--37748b674cd2.md#propdef-counter-increment) or ['content'](css2--generate.html--37748b674cd2.md#propdef-content) on an element or pseudo-element refers to a counter that is not in the scope of any ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset), implementations should behave as though a ['counter-reset'](css2--generate.html--37748b674cd2.md#propdef-counter-reset) had reset the counter to 0 on that element or pseudo-element.

In the example above, an OL will create a counter, and all children of the OL will refer to that counter.

If we denote by item\[n\] the n<sup>th</sup> instance of the "item" counter, and by "{" and "}" the beginning and end of a scope, then the following HTML fragment will use the indicated counters. (We assume the style sheet as given in the example above).

```text

<OL>                    <!-- {item[0]=0        -->
  <LI>item</LI>         <!--  item[0]++ (=1)   -->
  <LI>item              <!--  item[0]++ (=2)   -->
    <OL>                <!--  {item[1]=0       -->
      <LI>item</LI>     <!--   item[1]++ (=1)  -->
      <LI>item</LI>     <!--   item[1]++ (=2)  -->
      <LI>item          <!--   item[1]++ (=3)  -->
        <OL>            <!--   {item[2]=0      -->
          <LI>item</LI> <!--    item[2]++ (=1) -->
        </OL>           <!--                   -->
        <OL>            <!--   }{item[2]=0     -->
          <LI>item</LI> <!--    item[2]++ (=1) -->
        </OL>           <!--                   -->
      </LI>             <!--   }               -->
      <LI>item</LI>     <!--   item[1]++ (=4)  -->
    </OL>               <!--                   -->
  </LI>                 <!--  }                -->
  <LI>item</LI>         <!--  item[0]++ (=3)   -->
  <LI>item</LI>         <!--  item[0]++ (=4)   -->
</OL>                   <!--                   -->
<OL>                    <!-- }{item[0]=0       -->
  <LI>item</LI>         <!--  item[0]++ (=1)   -->
  <LI>item</LI>         <!--  item[0]++ (=2)   -->
</OL>                   <!--                   -->
```
> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> Another example, showing how scope works when counters are used on elements that are not nested, is the following. This shows how the style rules given above to number chapters and sections would apply to the markup given.
>
> ```text
> 
>                      <!--"chapter" counter|"section" counter -->
> <body>               <!-- {chapter=0      |                  -->
>   <h1>About CSS</h1> <!--  chapter++ (=1) | {section=0       -->
>   <h2>CSS 2</h2>     <!--                 |  section++ (=1)  -->
>   <h2>CSS 2.1</h2>   <!--                 |  section++ (=2)  -->
>   <h1>Style</h1>     <!--  chapter++ (=2) |}{ section=0      -->
> </body>              <!--                 | }                -->
> ```
The 'counters()' function generates a string composed of all of the counters with the same name that are in scope, separated by a given string.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> The following style sheet numbers nested list items as "1", "1.1", "1.1.1", etc.
>
> ```text
> 
> OL { counter-reset: item }
> LI { display: block }
> LI:before { content: counters(item, ".") " "; counter-increment: item }
> ```
<a id="counter-styles"></a>

### 12.4.2 Counter styles

By default, counters are formatted with decimal numbers, but all the styles available for the ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type) property are also available for counters. The notation is:

```text

counter(name)
```
for the default style, or:

```text

counter(name, <'list-style-type'>)
```
All the styles are allowed, including 'disc', 'circle', 'square', and 'none'.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> ```text
> 
> H1:before        { content: counter(chno, upper-latin) ". " }
> H2:before        { content: counter(section, upper-roman) " - " }
> BLOCKQUOTE:after { content: " [" counter(bq, lower-greek) "]" }
> DIV.note:before  { content: counter(notecntr, disc) " " }
> P:before         { content: counter(p, none) }
> ```
<a id="undisplayed-counters"></a>

### 12.4.3 Counters in elements with 'display: none'

An element that is not displayed (['display'](css2--visuren.html--3f334c530cf4.md#propdef-display) set to 'none') cannot increment or reset a counter.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, with the following style sheet, H2s with class "secret" do not increment 'count2'.
>
> ```text
> 
> H2.secret {counter-increment: count2; display: none}
> ```
Pseudo-elements that are not generated also cannot increment or reset a counter.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, the following does not increment 'heading':
>
> ```text
> 
> h1::before {
>     content: normal;
>     counter-increment: heading;
> }
> ```
Elements with ['visibility'](css2--visufx.html--2bc674cb7ab0.md#propdef-visibility) set to 'hidden', on the other hand, <em>do</em> increment counters.

<a id="lists"></a>

## 12.5 Lists

CSS 2.1 offers basic visual formatting of lists. An element with 'display: list-item' generates a [principal block box](css2--visuren.html--3f334c530cf4.md#principal-box) for the element's content and, depending on the values of 'list-style-type' and 'list-style-image', possibly also a marker box as a visual indication that the element is a list item.

<a id="x30"></a>

The list properties describe basic visual formatting of lists: they allow style sheets to specify the marker type (image, glyph, or number), and the marker position with respect to the principal box (outside it or within it before content). They do not allow authors to specify distinct style (colors, fonts, alignment, etc.) for the list marker or adjust its position with respect to the principal box; these may be derived from the principal box.

The [background properties](css2--colors.html--5784063d2778.md#background-properties) apply to the principal box only; an 'outside' marker box is transparent.

<a id="list-style"></a>

### 12.5.1 Lists: the ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type), ['list-style-image'](css2--generate.html--37748b674cd2.md#propdef-list-style-image), ['list-style-position'](css2--generate.html--37748b674cd2.md#propdef-list-style-position), and ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) properties

<a id="value-def-disc"></a>

<a id="value-def-circle"></a>

<a id="value-def-square"></a>

Glyphs are specified with <strong><span title="disc"><a>disc</a></span></strong>, <strong><span title="circle"><a>circle</a></span></strong>, and <strong><span title="square"><a>square</a></span></strong>. Their exact rendering depends on the user agent.

Numbering systems are specified with:

<a id="value-def-decimal"></a>

<strong>decimal</strong>

Decimal numbers, beginning with 1.

<a id="value-def-decimal-leading-zero"></a>

<strong><span title="decimal-leading-zero"><a>decimal-leading-zero</a></span></strong>

Decimal numbers padded by initial zeros (e.g., 01, 02, 03, ..., 98, 99).

<a id="value-def-lower-roman"></a>

<strong><span title="lower-roman"><a>lower-roman</a></span></strong>

Lowercase roman numerals (i, ii, iii, iv, v, etc.).

<a id="value-def-upper-roman"></a>

<strong><span title="upper-roman"><a>upper-roman</a></span></strong>

Uppercase roman numerals (I, II, III, IV, V, etc.).

<a id="value-def-georgian"></a>

<strong><span title="georgian"><a>georgian</a></span></strong>

Traditional Georgian numbering (an, ban, gan, ..., he, tan, in, in-an, ...).

<a id="value-def-armenian"></a>

<strong><span title="armenian"><a>armenian</a></span></strong>

Traditional uppercase Armenian numbering.

Alphabetic systems are specified with:

<a id="value-def-lower-latin"></a>

<strong><span title="lower-latin"><a>lower-latin</a></span></strong> or <strong>lower-alpha</strong>

Lowercase ascii letters (a, b, c, ... z).

<a id="value-def-upper-latin"></a>

<strong><span title="upper-latin"><a>upper-latin</a></span></strong> or <strong>upper-alpha</strong>

Uppercase ascii letters (A, B, C, ... Z).

<a id="value-def-lower-greek"></a>

<strong><span title="lower-greek"><a>lower-greek</a></span></strong>

Lowercase classical Greek alpha, beta, gamma, ... (α, β, γ, ...)

This specification does not define how alphabetic systems wrap at the end of the alphabet. For instance, after 26 list items, 'lower-latin' rendering is undefined. Therefore, for long lists, we recommend that authors specify true numbers.

CSS 2.1 does not define how the list numbering is reset and incremented. This is expected to be defined in the CSS List Module [\[CSS3LIST\]](css2--refs.html--f208d881d0b7.md#ref-CSS3LIST).

For example, the following HTML document:

```text

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN">
<HTML>
   <HEAD>
     <TITLE>Lowercase latin numbering</TITLE>
     <STYLE type="text/css">
          ol { list-style-type: lower-roman }   
     </STYLE>
  </HEAD>
  <BODY>
    <OL>
      <LI> This is the first item.
      <LI> This is the second item.
      <LI> This is the third item.
    </OL>
  </BODY>
</HTML>
```
might produce something like this:

```text

  i This is the first item.
 ii This is the second item.
iii This is the third item.
```
The list marker alignment (here, right justified) depends on the user agent.

<strong>'list-style-image'</strong>

|                       |                                                                                                                                                                                      |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| <em>Value:</em>   | [\<uri\>](css2--syndata.html--02e71c159e14.md#value-def-uri) \| none \| [inherit](css2--cascade.html--c7aff33e6f0d.md#value-def-inherit) |
| <em>Initial:</em>   | none                                                                                                                                                                                 |

| <em>Percentages:</em>   | N/A                                                                                                                                                                                  |
| <em>Media:</em>   | [visual](css2--media.html--3a324a170379.md#visual-media-group)                                                                                                 |
| <em>Computed value:</em>   | absolute URI or 'none'                                                                                                                                                               |

This property sets the image that will be used as the list item marker. When the image is available, it will replace the marker set with the ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type) marker.

The size of the image is calculated from the following rules:

1.  If the image has a intrinsic width and height, the used width and height are the intrinsic width and height.
2.  Otherwise, if the image has an intrinsic ratio and either an intrinsic width or an intrinsic height, the used width/height is the same as the provided intrinsic width/height, and the used value of the missing dimension is calculated from the provided dimension and the ratio.
3.  Otherwise, if the image has an intrinsic ratio, the used width is 1em and the used height is calculated from this width and the intrinsic ratio. If this would produce a height larger than 1em, then the used height is instead set to 1em and the used width is calculated from this height and the intrinsic ratio.
4.  Otherwise, the image's used width is its intrinsic width if it has one, or else 1em. The image's used height is its intrinsic height if it has one, or else 1em.

>
> Example(s):
>

>
> ```text
> 
> ul { list-style-image: url("http://png.com/ellipse.png") }
> ```

This property specifies the position of the marker box with respect to the principal block box. Values have the following meanings:

<strong>outside</strong>  
The marker box is outside the principal block box. The position of the list-item marker adjacent to floats is undefined in CSS 2.1. CSS 2.1 does not specify the precise location of the marker box or its position in the painting order, but does require that for list items whose 'direction' property is 'ltr' the marker box be on the left side of the content and for elements whose 'direction' property is 'rtl' the marker box be on the right side of the content. The marker box is fixed with respect to the principal block box's border and does not scroll with the principal block box's content. In CSS 2.1, a UA may hide the marker if the element's ['overflow'](css2--visufx.html--2bc674cb7ab0.md#propdef-overflow) is other than 'visible'. (This is expected to change in the future.) The size or contents of the marker box may affect the height of the principal block box and/or the height of its first line box, and in some cases may cause the creation of a new line box. <strong data-conversion-semantic="note">Note:</strong> <strong>Note:</strong> This interaction may be more precisely defined in a future level of CSS.

<strong>inside</strong>  
The marker box is placed as the first inline box in the principal block box, before the element's content and before any :before pseudo-elements. CSS 2.1 does not specify the precise location of the marker box.

```text

<HTML>

      ul.compact { list-style: inside }
    </STYLE>
  </HEAD>
  <BODY>
    <UL>
      <LI>first list item comes first
      <LI>second list item comes second
    </UL>

    <UL class="compact">
      <LI>first list item comes first
      <LI>second list item comes second
    </UL>
  </BODY>
</HTML>
```

The ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) property is a shorthand notation for setting the three properties ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type), ['list-style-image'](css2--generate.html--37748b674cd2.md#propdef-list-style-image), and ['list-style-position'](css2--generate.html--37748b674cd2.md#propdef-list-style-position) at the same place in the style sheet.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> ```text
> 
> ul { list-style: upper-roman inside }  /* Any "ul" element */
> ul > li > ul { list-style: circle outside } /* Any "ul" child 
>                                              of an "li" child 
>                                              of a "ul" element */
> ```
Although authors may specify ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) information directly on list item elements (e.g., "li" in HTML), they should do so with care. The following rules look similar, but the first declares a [descendant selector](css2--selector.html--f66f7c932788.md#descendant-selectors) and the second a (more specific) [child selector.](css2--selector.html--f66f7c932788.md#child-selectors)

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> ol.alpha li   { list-style: lower-alpha } /* Any "li" descendant of an "ol" */ 
> ol.alpha > li { list-style: lower-alpha } /* Any "li" child of an "ol" */
> ```
Authors who use only the [descendant selector](css2--selector.html--f66f7c932788.md#descendant-selectors) may not achieve the results they expect. Consider the following rules:

```text

<HTML>
  <HEAD>
    <TITLE>WARNING: Unexpected results due to cascade</TITLE>
    <STYLE type="text/css">
      ol.alpha li  { list-style: lower-alpha }
      ul li        { list-style: disc }
    </STYLE>
  </HEAD>
  <BODY>
    <OL class="alpha">
      <LI>level 1
      <UL>
         <LI>level 2
      </UL>
    </OL>
  </BODY>
</HTML>
```
The desired rendering would have level 1 list items with 'lower-alpha' labels and level 2 items with 'disc' labels. However, the [cascading order](css2--cascade.html--c7aff33e6f0d.md#cascading-order) will cause the first style rule (which includes specific class information) to mask the second. The following rules solve the problem by employing a [child selector](css2--selector.html--f66f7c932788.md#child-selectors) instead:

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> ol.alpha > li  { list-style: lower-alpha }
> ul li   { list-style: disc }
> ```
Another solution would be to specify ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) information only on the list type elements:

> <strong data-conversion-semantic="example">Example</strong>
>
> ```text
> 
> ol.alpha  { list-style: lower-alpha }
> ul        { list-style: disc }
> ```
Inheritance will transfer the ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) values from OL and UL elements to LI elements. This is the recommended way to specify list style information.

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> A URI value may be combined with any other value, as in:
>
> ```text
> 
> ul { list-style: url("http://png.com/ellipse.png") disc }
> ```
>
> In the example above, the 'disc' will be used when the image is unavailable.

A value of 'none' within the ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) property sets whichever of ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type) and ['list-style-image'](css2--generate.html--37748b674cd2.md#propdef-list-style-image) are not otherwise specified to 'none'. However, if both are otherwise specified, the declaration is in error (and thus ignored).

> <strong data-conversion-semantic="example">Example</strong>
>
> Example(s):
>
> For example, a value of 'none' for the ['list-style'](css2--generate.html--37748b674cd2.md#propdef-list-style) property sets both ['list-style-type'](css2--generate.html--37748b674cd2.md#propdef-list-style-type) and ['list-style-image'](css2--generate.html--37748b674cd2.md#propdef-list-style-image) to 'none':
>
> ```text
> 
> ul { list-style: none }
> ```
>
> The result is that no list-item marker is displayed.
