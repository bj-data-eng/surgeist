- <a id="unicode-unbreakable"></a>[](#unicode-unbreakable) CSS never allows <a id="ref-for-soft-wrap-opportunity④⑥"></a>[soft wrap opportunities](https://drafts.csswg.org/css-text-4/#soft-wrap-opportunity) within <a id="ref-for-typographic-character-unit②①"></a>[typographic character units](https://drafts.csswg.org/css-text-4/#typographic-character-unit). Thus, the <code>CM</code> and <code>SG</code> Unicode line breaking classes must always be honored. [\[UAX14\]](https://drafts.csswg.org/css-text-4/#biblio-uax14)

- <a id="break-prioritization"></a>[](#break-prioritization) UAs that allow wrapping at punctuation other than <a id="ref-for-word-separator②"></a>[word separators](https://drafts.csswg.org/css-text-4/#word-separator) in writing systems that use them <em>should</em> prioritize breakpoints. (For example, if breaks after slashes are given a lower priority than spaces, the sequence “check /etc” will never break between the "/" and the "e".) As long as care is taken to avoid such awkward breaks, allowing breaks at appropriate punctuation other than <a id="ref-for-word-separator③"></a>word separators is recommended, as it results in more even-looking margins, particularly in narrow measures. The UA may use the width of the containing block, the text’s language, the <a id="ref-for-propdef-line-break⑨"></a>[line-break](https://drafts.csswg.org/css-text-4/#propdef-line-break) value, and other factors in assigning priorities: CSS does not define prioritization of <a id="ref-for-soft-wrap-opportunity④⑦"></a>[soft wrap opportunities](https://drafts.csswg.org/css-text-4/#soft-wrap-opportunity). Prioritization of <a id="ref-for-word-separator④"></a>word separators is not expected, however, if <a id="ref-for-propdef-word-break②⑦"></a>[word-break: break-all](https://drafts.csswg.org/css-text-4/#propdef-word-break) is specified (since this value explicitly requests line breaking behavior not based on breaking at <a id="ref-for-word-separator⑤"></a>word separators)—​and is forbidden under <a id="ref-for-propdef-line-break①⓪"></a>line-break: anywhere.

- <a id="ignored-boxes"></a> [](#ignored-boxes) <a id="ref-for-out-of-flow③"></a>[Out-of-flow boxes](https://drafts.csswg.org/css-display-4/#out-of-flow) and <a id="ref-for-inline-box⑤"></a>[inline box](https://drafts.csswg.org/css-display-4/#inline-box) boundaries do not introduce a <a id="ref-for-forced-line-break①①"></a>[forced line break](https://drafts.csswg.org/css-text-4/#forced-line-break) or <a id="ref-for-soft-wrap-opportunity④⑧"></a>[soft wrap opportunity](https://drafts.csswg.org/css-text-4/#soft-wrap-opportunity) in the flow.

- <a id="atomic-compat-wrap"></a> [](#atomic-compat-wrap) For Web-compatibility there is a <a id="ref-for-soft-wrap-opportunity④⑨"></a>[soft wrap opportunity](https://drafts.csswg.org/css-text-4/#soft-wrap-opportunity) before and after each replaced element or other <a id="ref-for-atomic-inline"></a>[atomic inline](https://drafts.csswg.org/css-display-4/#atomic-inline), even when adjacent to a character that would normally suppress them, including U+00A0 NO-BREAK SPACE.
