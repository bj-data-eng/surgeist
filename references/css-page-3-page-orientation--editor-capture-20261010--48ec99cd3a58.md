#### 7.1.2.  Rotating The Printed Page: the <a id="ref-for-descdef-page-page-orientation"></a>[page-orientation](#descdef-page-page-orientation) property[](#page-orientation-prop)

| Field | Definition |
| --- | --- |
| Name: | <a id="descdef-page-page-orientation"></a>page-orientation |
| For: | <a id="ref-for-at-ruledef-page①④"></a>[&#64;page](https://drafts.csswg.org/css-page-3/#at-ruledef-page) |
| Value: | upright <a id="ref-for-comb-one⑥"></a>[\|](https://drafts.csswg.org/css-values-4/#comb-one) rotate-left <a id="ref-for-comb-one⑦"></a>[\|](https://drafts.csswg.org/css-values-4/#comb-one) rotate-right |
| Initial: | upright |
| Computed value: | as specified |

High-quality printing implementations can handle pages of varying sizes and orientations, so an author can choose the size of a page according to what’s best for that page’s content. For example, they might use <code>size: letter portrait;</code> for most pages in a document, but switch to <code>size: letter landscape;</code> to lay out a wide information table.

However, handling content flowing across pages of differing widths is a relatively complex task, and is not yet solved in many popular printing implementations (notably, web browsers). The <a id="ref-for-descdef-page-page-orientation①"></a>[page-orientation](#descdef-page-page-orientation) descriptor is intended to help such implementations, allowing them to lay out pages in a single consistent size, but change the orientation post-layout in the output medium (such as PDF), so that pages which want to be displayed in a different orientation can do so.

Its values are defined as:

<a id="valdef-page-orientation-upright"></a>upright

No special orientation is applied; the page is laid out and formatted as normal.

<a id="valdef-page-orientation-rotate-left"></a>rotate-left

After the page has been laid out, if the output medium supports rotation, this value indicates that the page must be displayed rotated a quarter turn to the left (counter-clockwise) of how it was laid out.

<a id="valdef-page-orientation-rotate-right"></a>rotate-right

Same as <a id="ref-for-valdef-page-orientation-rotate-left"></a>[rotate-left](#valdef-page-orientation-rotate-left), except the page must be displayed rotated a quarter turn to the right (clockwise) of how it was laid out.

> Note: Margin boxes and other positional things have no special interaction with this property; they’ll be laid out as normal in the unrotated page, then rotated along with everything else.

**Informative note** (the following complete block was `class="note"` in the source):

> This property is intended as a stop-gap for less-capable implementations, allowing them to still print documents with a mix of portrait and landscape orientations before they have the ability to flow content across differently-size pages. It requires some awkward contortions to use, such as specifying that a wide table containing only English actually has a vertical <a id="ref-for-propdef-writing-mode①"></a>[writing-mode](https://drafts.csswg.org/css-writing-modes-4/#propdef-writing-mode) so it’ll lay out "sideways", but be rotated back to upright for readability in the printed output.
>
> There should be no need to use this property in high-quality printing implementations; instead, use <a id="ref-for-descdef-page-size⑧"></a>[size](https://drafts.csswg.org/css-page-3/#descdef-page-size) to control <a id="ref-for-valdef-page-size-portrait③"></a>[portrait](https://drafts.csswg.org/css-page-3/#valdef-page-size-portrait) vs <a id="ref-for-valdef-page-size-landscape②"></a>[landscape](https://drafts.csswg.org/css-page-3/#valdef-page-size-landscape) orientation of a page.
