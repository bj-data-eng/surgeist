# <a id="title"></a>Fullscreen API ([Commit 7c38d773117aa1e6bfa13754afe77483f40c908f](https://github.com/whatwg/fullscreen/commit/7c38d773117aa1e6bfa13754afe77483f40c908f))

## <a id="abstract"></a>Abstract

The Fullscreen API standard defines an API for elements to display themselves fullscreen.

## <a id="terminology"></a>1. Terminology

This specification depends on the Infra Standard. [\[INFRA\]](#biblio-infra)

Most terminology used in this specification is from CSS, DOM, HTML, and Web IDL. [\[CSS\]](#biblio-css) [\[DOM\]](#biblio-dom) [\[HTML\]](#biblio-html) [\[WEBIDL\]](#biblio-webidl)

## <a id="model"></a>2. Model

<a id="ref-for-concept-element"></a>

All [elements](https://dom.spec.whatwg.org/#concept-element) have an associated <a id="fullscreen-flag"></a>fullscreen flag. Unless stated otherwise it is unset.

All <code><a href="https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element">iframe</a></code> [elements](https://dom.spec.whatwg.org/#concept-element) have an associated <a id="iframe-fullscreen-flag"></a>iframe fullscreen flag. Unless stated otherwise it is unset.

<a id="ref-for-fullscreen-flag"></a>

All [documents](https://dom.spec.whatwg.org/#concept-document) have an associated <a id="fullscreen-element"></a>fullscreen element. The [fullscreen element](#fullscreen-element) is the topmost [element](https://dom.spec.whatwg.org/#concept-element) in the [document](https://dom.spec.whatwg.org/#concept-document)’s [top layer](https://drafts.csswg.org/css-position-4/#document-top-layer) whose [fullscreen flag](#fullscreen-flag) is set, if any, and null otherwise.

It is initially empty.

To <a id="fullscreen-an-element"></a>fullscreen an <var>element</var>:

1.  <a id="ref-for-topmost-popover-ancestor"></a>

    Let <var>hideUntil</var> be the result of running [topmost popover ancestor](https://html.spec.whatwg.org/multipage/popover.html#topmost-popover-ancestor) given <var>element</var>, null, and false.

2.  <a id="ref-for-hide-popovers-until"></a>

    <a id="ref-for-concept-node-document"></a>

    Run [hide popovers until](https://html.spec.whatwg.org/multipage/popover.html#hide-popovers-until) given <var>element</var>’s [node document](https://dom.spec.whatwg.org/#concept-node-document), <var>hideUntil</var>, false, and true.

3.  <a id="ref-for-fullscreen-flag①"></a>

    Set <var>element</var>’s [fullscreen flag](#fullscreen-flag).

4.  <a id="ref-for-remove-an-element-from-the-top-layer-immediately"></a>

    [Remove from the top layer immediately](https://drafts.csswg.org/css-position-4/#remove-an-element-from-the-top-layer-immediately) given <var>element</var>.

5.  <a id="ref-for-add-an-element-to-the-top-layer"></a>

    [Add to the top layer](https://drafts.csswg.org/css-position-4/#add-an-element-to-the-top-layer) given <var>element</var>.

To <a id="unfullscreen-an-element"></a>unfullscreen an <var>element</var>, unset <var>element</var>’s [fullscreen flag](#fullscreen-flag), [iframe fullscreen flag](#iframe-fullscreen-flag) (if any), and [keyboard lock flag](#keyboard-lock-flag), and [remove from the top layer immediately](https://drafts.csswg.org/css-position-4/#remove-an-element-from-the-top-layer-immediately) given <var>element</var>.

1.  <a id="ref-for-fullscreen-element①"></a>

2.  <a id="ref-for-unfullscreen-an-element①"></a>

    <a id="ref-for-fullscreen-flag④"></a>

    <a id="ref-for-document-top-layer②"></a>

    <a id="ref-for-fullscreen-element②"></a>

3.  <a id="ref-for-exit-fullscreen"></a>

    [Exit fullscreen](#exit-fullscreen) <var>document</var>.

<a id="ref-for-concept-node-remove-ext"></a>

<a id="removing-steps"></a>Whenever the [removing steps](https://dom.spec.whatwg.org/#concept-node-remove-ext) run with a <var>removedNode</var>, run these steps:

2.  <a id="ref-for-concept-shadow-including-inclusive-descendant"></a>

    <a id="ref-for-fullscreen-flag⑤"></a>

    <a id="ref-for-concept-shadow-including-tree-order"></a>

    Let <var>nodes</var> be <var>removedNode</var>’s [shadow-including inclusive descendants](https://dom.spec.whatwg.org/#concept-shadow-including-inclusive-descendant) that have their [fullscreen flag](#fullscreen-flag) set, in [shadow-including tree order](https://dom.spec.whatwg.org/#concept-shadow-including-tree-order).

3.  <a id="ref-for-list-iterate"></a>

    [For each](https://infra.spec.whatwg.org/#list-iterate) <var>node</var> in <var>nodes</var>:

    1.  <a id="ref-for-fullscreen-element③"></a>

        <a id="ref-for-exit-fullscreen①"></a>

        If <var>node</var> is <var>document</var>’s [fullscreen element](#fullscreen-element), [exit fullscreen](#exit-fullscreen) <var>document</var>.

    2.  <a id="ref-for-unfullscreen-an-element②"></a>

        Otherwise, [unfullscreen <var>node</var>](#unfullscreen-an-element).

    3.  <a id="ref-for-document-top-layer③"></a>

        <a id="ref-for-list-contain"></a>

        <a id="ref-for-remove-an-element-from-the-top-layer-immediately②"></a>

        If <var>document</var>’s [top layer](https://drafts.csswg.org/css-position-4/#document-top-layer) [contains](https://infra.spec.whatwg.org/#list-contain) <var>node</var>, [remove from the top layer immediately](https://drafts.csswg.org/css-position-4/#remove-an-element-from-the-top-layer-immediately) given <var>node</var>.

        <a id="ref-for-document-top-layer④"></a>

        <a id="ref-for-fullscreen-element④"></a>

        <a id="ref-for-the-dialog-element"></a>

        > <strong data-conversion-semantic="note">Note</strong>
        >
        > Other specifications can add and remove elements from [top layer](https://drafts.csswg.org/css-position-4/#document-top-layer), so <var>node</var> might not be <var>document</var>’s [fullscreen element](#fullscreen-element). For example, <var>node</var> could be an open <code><a href="https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element">dialog</a></code> element.

<a id="ref-for-unloading-document-cleanup-steps"></a>

<a id="ref-for-fully-exit-fullscreen"></a>

Whenever the [unloading document cleanup steps](https://html.spec.whatwg.org/multipage/document-lifecycle.html#unloading-document-cleanup-steps) run with a <var>document</var>, [fully exit fullscreen](#fully-exit-fullscreen) <var>document</var>.

<a id="ref-for-concept-document④"></a>

To <a id="run-the-fullscreen-steps"></a>run the fullscreen steps for a [document](https://dom.spec.whatwg.org/#concept-document) <var>document</var>, run these steps:

1.  <a id="ref-for-list-of-pending-fullscreen-events"></a>

    Let <var>pendingEvents</var> be <var>document</var>’s [list of pending fullscreen events](#list-of-pending-fullscreen-events).

2.  <a id="ref-for-list-empty"></a>

    <a id="ref-for-list-of-pending-fullscreen-events①"></a>

    [Empty](https://infra.spec.whatwg.org/#list-empty) <var>document</var>’s [list of pending fullscreen events](#list-of-pending-fullscreen-events).

3.  <a id="ref-for-list-iterate①"></a>

    [For each](https://infra.spec.whatwg.org/#list-iterate) (<var>type</var>, <var>element</var>) in <var>pendingEvents</var>:

    1.  <a id="ref-for-connected"></a>

        <a id="ref-for-concept-node-document②"></a>

        Let <var>target</var> be <var>element</var> if <var>element</var> is [connected](https://dom.spec.whatwg.org/#connected) and its [node document](https://dom.spec.whatwg.org/#concept-node-document) is <var>document</var>, and otherwise let <var>target</var> be <var>document</var>.

    2.  <a id="ref-for-concept-event-fire"></a>

        <a id="ref-for-dom-event-bubbles"></a>

        <a id="ref-for-dom-event-composed"></a>

        [Fire an event](https://dom.spec.whatwg.org/#concept-event-fire) named <var>type</var>, with its <code><a href="https://dom.spec.whatwg.org/#dom-event-bubbles">bubbles</a></code> and <code><a href="https://dom.spec.whatwg.org/#dom-event-composed">composed</a></code> attributes set to true, at <var>target</var>.

> <strong data-conversion-semantic="note">Note</strong>

> These steps integrate with the [event loop](https://html.spec.whatwg.org/multipage/webappapis.html#event-loop) defined in HTML. [\[HTML\]](#biblio-html)

```text
enum FullscreenNavigationUI {
  "auto",
  "show",
  "hide"
};

enum FullscreenKeyboardLock {
  "browser",
  "none"
};

dictionary FullscreenOptions {
  FullscreenKeyboardLock keyboardLock = "none";
  FullscreenNavigationUI navigationUI = "auto";
};

partial interface Element {
  Promise<undefined> requestFullscreen(optional FullscreenOptions options = {});

  attribute EventHandler onfullscreenchange;
  attribute EventHandler onfullscreenerror;
};

partial interface Document {
  [LegacyLenientSetter] readonly attribute boolean fullscreenEnabled;
  [LegacyLenientSetter, Unscopable] readonly attribute boolean fullscreen; // historical

  Promise<undefined> exitFullscreen();

  attribute EventHandler onfullscreenchange;
  attribute EventHandler onfullscreenerror;
};

partial interface mixin DocumentOrShadowRoot {
  [LegacyLenientSetter] readonly attribute Element? fullscreenElement;
};
```

<a id="ref-for-dom-fullscreennavigationui-auto①"></a>

When supplied, <var>options</var>’s <code><a href="#dom-fullscreenoptions-navigationui">navigationUI</a></code> member indicates whether showing navigation UI while in fullscreen is preferred or not. If set to "<code><a href="#dom-fullscreennavigationui-show">show</a></code>", navigation simplicity is preferred over screen space, and if set to "<code><a href="#dom-fullscreennavigationui-hide">hide</a></code>", more screen space is preferred. User agents are always free to honor user preference over the application’s. The default value "<code><a href="#dom-fullscreennavigationui-auto">auto</a></code>" indicates no application preference.

<a id="ref-for-dom-fullscreenoptions-keyboardlock"></a>

When supplied, <var>options</var>’s <code><a href="#dom-fullscreenoptions-keyboardlock">keyboardLock</a></code> member indicates whether the supplied keyboard lock mode will apply.

The <a id="dom-element-requestfullscreen"></a><code>requestFullscreen(<var>options</var>)</code> method steps are:

1.  <a id="ref-for-this"></a>

    <a id="ref-for-concept-node-document④"></a>

    Let <var>pendingDoc</var> be [this](https://webidl.spec.whatwg.org/#this)’s [node document](https://dom.spec.whatwg.org/#concept-node-document).

2.  Let <var>promise</var> be a new promise.

3.  <a id="ref-for-fully-active"></a>

    <a id="ref-for-exceptiondef-typeerror"></a>

    If <var>pendingDoc</var> is not [fully active](https://html.spec.whatwg.org/multipage/document-sequences.html#fully-active), then reject <var>promise</var> with a <code><a href="https://webidl.spec.whatwg.org/#exceptiondef-typeerror">TypeError</a></code> exception and return <var>promise</var>.

4.  Let <var>error</var> be false.

5.  If any of the following conditions are false, then set <var>error</var> to true:

    - <a id="ref-for-this①"></a>

      <a id="ref-for-concept-element-namespace①"></a>

      <a id="ref-for-html-namespace①"></a>

      <a id="ref-for-this②"></a>

      [This](https://webidl.spec.whatwg.org/#this)’s [namespace](https://dom.spec.whatwg.org/#concept-element-namespace) is the [HTML namespace](https://infra.spec.whatwg.org/#html-namespace) or [this](https://webidl.spec.whatwg.org/#this) is an [SVG `svg`](https://www.w3.org/TR/SVG11/struct.html#SVGElement) or [MathML `math`](https://www.w3.org/Math/draft-spec/chapter2.html#interf.toplevel) element. [\[SVG\]](#biblio-svg) [\[MATHML\]](#biblio-mathml)

    - <a id="ref-for-this③"></a>

      <a id="ref-for-the-dialog-element①"></a>

      [This](https://webidl.spec.whatwg.org/#this) is not a <code><a href="https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element">dialog</a></code> element.

    - <a id="ref-for-fullscreen-element-ready-check"></a>

      <a id="ref-for-this④"></a>

      The [fullscreen element ready check](#fullscreen-element-ready-check) for [this](https://webidl.spec.whatwg.org/#this) returns true.

    - <a id="ref-for-fullscreen-is-supported①"></a>

      [Fullscreen is supported](#fullscreen-is-supported).

    - <a id="ref-for-this⑤"></a>

## <a id="keyboard-locking"></a>6. Keyboard Locking

Keyboard locking enhances the functionality of web applications running in fullscreen by allowing them to intercept certain key inputs that would typically be handled by either the system or the user agent. This is useful in scenarios such as gaming or remote desktop applications, where keys like ESC or function keys are integral to the application’s functionality.

<a id="ref-for-keyboard-lock②"></a>

<a id="ref-for-keyboard-lock③"></a>

<a id="ref-for-dom-event-preventdefault"></a>

A [keyboard lock](#keyboard-lock) enables web applications to capture and handle key inputs directly, bypassing the default behavior typically executed by the user agent or operating system. Key events that would normally trigger user agent or system-level actions are instead redirected to the web application in fullscreen. Such key events (for individual keys or keyboard shortcuts) may either have no action while [keyboard lock](#keyboard-lock) is active, or it could still have the same action but allow the web page to call <code><a href="https://dom.spec.whatwg.org/#dom-event-preventdefault">preventDefault()</a></code> to cancel the action.

<a id="ref-for-concept-document①⓪"></a>

<a id="ref-for-keyboard-lock④"></a>

Whenever a [document](https://dom.spec.whatwg.org/#concept-document)’s [keyboard lock](#keyboard-lock) is changed from active to inactive, user agents must deactivate the keyboard lock and restore the handling of keyboard inputs to the default behavior of the user agent and the operating system.

User agents should reserve an additional input for the purposes of exiting fullscreen. There are also some system-level key sequences or combinations that cannot be intercepted for security reasons, such as Ctrl+Alt+Del on Windows.

For example, user agents that use the Esc key to exit fullscreen use keyboard lock to prevent immediate exit on key press, and instead require a long press to exit fullscreen. Some such user agents also implicitly grant partial keyboard lock to fullscreen session, in which case the Esc key might be the only key that is affected by explicit keyboard lock.

## <a id="permissions-policy-integration"></a>7. <a id="feature-policy-integration"></a>Permissions Policy Integration

<a id="ref-for-policy-controlled-feature"></a>

<a id="fullscreen-feature"></a>

<a id="ref-for-policy-controlled-feature-default-allowlist"></a>

Its [default allowlist](https://w3c.github.io/webappsec-permissions-policy/#policy-controlled-feature-default-allowlist) is `'self'`.

If disabled in any document, no content in the document will be [allowed to use](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#allowed-to-use) fullscreen.
>
> <a id="ref-for-attr-iframe-allowfullscreen"></a>

> <a id="ref-for-attr-iframe-allow"></a>

## <a id="security-and-privacy-considerations"></a>8. Security and Privacy Considerations

<a id="ref-for-dom-element-requestfullscreen③"></a>

User agents should ensure, e.g. by means of an overlay, that the end user is aware something is displayed fullscreen. User agents should provide a means of exiting fullscreen that always works and advertise this to the user. This is to prevent a site from spoofing the end user by recreating the user agent or even operating system environment when fullscreen. See also the definition of <code><a href="#dom-element-requestfullscreen">requestFullscreen()</a></code>.

<a id="ref-for-child-navigable"></a>

<a id="ref-for-attr-iframe-allowfullscreen②"></a>

<a id="ref-for-the-iframe-element③"></a>

<a id="ref-for-attr-iframe-allow①"></a>

<a id="ref-for-the-iframe-element④"></a>

<a id="ref-for-permissions-policy-header"></a>

<a id="ref-for-concept-document①②"></a>

To enable content in a [child navigable](https://html.spec.whatwg.org/multipage/document-sequences.html#child-navigable) to go fullscreen, it needs to be specifically allowed via permissions policy, either through the <code><a href="https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-allowfullscreen">allowfullscreen</a></code> attribute of the HTML <code><a href="https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element">iframe</a></code> element, or an appropriate declaration in the <code><a href="https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-allow">allow</a></code> attribute of the HTML <code><a href="https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element">iframe</a></code> element, or through a \`[`Permissions-Policy`](https://w3c.github.io/webappsec-permissions-policy/#permissions-policy-header)\` HTTP header delivered with the [document](https://dom.spec.whatwg.org/#concept-document) through which it is nested.

This prevents e.g. content from third parties to go fullscreen without explicit permission.

<a id="ref-for-keyboard-lock⑤"></a>

When applying a [keyboard lock](#keyboard-lock), only a limited set of keys, primarily those not involving system control or privacy risks (like Alt+Tab, Ctrl+Alt+Del), can be locked via the API.

<a id="ref-for-keyboard-lock⑥"></a>

When applying a [keyboard lock](#keyboard-lock), user agents should implement safeguards to prevent abuse of this feature, such as allowing users to override the lock.

<a id="ref-for-keyboard-lock⑦"></a>

<a id="ref-for-keyboard-lock⑧"></a>

<a id="ref-for-dom-element-requestfullscreen④"></a>

User agents may provide a user preference to ignore [keyboard lock](#keyboard-lock) (with any granularity, e.g. for a specific site, or globally). Similarly, some platforms might not have a keyboard, where user agents may ignore the [keyboard lock](#keyboard-lock) state. However, this should not affect the web-observable behavior of the <code><a href="#dom-element-requestfullscreen">requestFullscreen()</a></code> method or be exposed in other ways, to avoid fingerprinting.
