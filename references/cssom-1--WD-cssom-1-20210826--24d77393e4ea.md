## <a id="introduction"></a>1. Introduction

This document formally specifies the core features of the CSS Object Model (CSSOM). Other documents in the CSSOM family of specifications as well as other CSS related specifications define extensions to these core features.

The core features of the CSSOM are oriented towards providing basic capabilities to author-defined scripts to permit access to and manipulation of style related state information and processes.

The features defined below are fundamentally based on prior specifications of the W3C DOM Working Group, primarily [\[DOM\]](#biblio-dom). The purposes of the present document are (1) to improve on that prior work by providing more technical specificity (so as to improve testability and interoperability), (2) to deprecate or remove certain less-widely implemented features no longer considered to be essential in this context, and (3) to newly specify certain extensions that have been or expected to be widely implemented.

### <a id="common-serializing-idioms"></a>2.1. Common Serializing Idioms

To <a id="escape-a-character"></a>escape a character means to create a string of "`\`" (U+005C), followed by the character.

To <a id="escape-a-character-as-code-point"></a>escape a character as code point means to create a string of "`\`" (U+005C), followed by the Unicode code point as the smallest possible number of hexadecimal digits in the range 0-9 a-f (U+0030 to U+0039 and U+0061 to U+0066) to represent the code point in base 16, followed by a single SPACE (U+0020).

To <a id="serialize-an-identifier"></a>serialize an identifier means to create a string represented by the concatenation of, for each character of the identifier:

- If the character is NULL (U+0000), then the REPLACEMENT CHARACTER (U+FFFD).

- <a id="ref-for-escape-a-character-as-code-point"></a>

  If the character is in the range \[&#x5C;1-&#x5C;1f\] (U+0001 to U+001F) or is U+007F, then the character [escaped as code point](#escape-a-character-as-code-point).

- <a id="ref-for-escape-a-character-as-code-point①"></a>

  If the character is the first character and is in the range \[0-9\] (U+0030 to U+0039), then the character [escaped as code point](#escape-a-character-as-code-point).

- <a id="ref-for-escape-a-character-as-code-point②"></a>

  If the character is the second character and is in the range \[0-9\] (U+0030 to U+0039) and the first character is a "`-`" (U+002D), then the character [escaped as code point](#escape-a-character-as-code-point).

- <a id="ref-for-escape-a-character"></a>

  If the character is the first character and is a "`-`" (U+002D), and there is no second character, then the [escaped](#escape-a-character) character.

- If the character is not handled by one of the above rules and is greater than or equal to U+0080, is "`-`" (U+002D) or "`_`" (U+005F), or is in one of the ranges \[0-9\] (U+0030 to U+0039), \[A-Z\] (U+0041 to U+005A), or &#x5C;\[a-z\] (U+0061 to U+007A), then the character itself.

- <a id="ref-for-escape-a-character①"></a>

  Otherwise, the [escaped](#escape-a-character) character.

To <a id="serialize-a-string"></a>serialize a string means to create a string represented by '"' (U+0022), followed by the result of applying the rules below to each character of the given string, followed by '"' (U+0022):

- If the character is NULL (U+0000), then the REPLACEMENT CHARACTER (U+FFFD).

- <a id="ref-for-escape-a-character-as-code-point③"></a>

  If the character is in the range \[&#x5C;1-&#x5C;1f\] (U+0001 to U+001F) or is U+007F, the character [escaped as code point](#escape-a-character-as-code-point).

- <a id="ref-for-escape-a-character②"></a>

  If the character is '"' (U+0022) or "`\`" (U+005C), the [escaped](#escape-a-character) character.

- Otherwise, the character itself.

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: "`'`" (U+0027) is not escaped because strings are always serialized with '"' (U+0022).

<a id="ref-for-serialize-a-string"></a>

To <a id="serialize-a-url"></a>serialize a URL means to create a string represented by "`url(`", followed by the [serialization](#serialize-a-string) of the URL as a string, followed by "`)`".

<a id="ref-for-serialize-a-string①"></a>

To <a id="serialize-a-local"></a>serialize a LOCAL means to create a string represented by "`local(`", followed by the [serialization](#serialize-a-string) of the LOCAL as a string, followed by "`)`".

To <a id="serialize-a-comma-separated-list"></a>serialize a comma-separated list concatenate all items of the list in list order while separating them by "` ,  `", i.e., COMMA (U+002C) followed by a single SPACE (U+0020).

To <a id="serialize-a-whitespace-separated-list"></a>serialize a whitespace-separated list concatenate all items of the list in list order while separating them by "`   `", i.e., a single SPACE (U+0020).

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: When serializing a list according to the above rules, extraneous whitespace is not inserted prior to the first item or subsequent to the last item. Unless otherwise specified, an empty list is serialized as the empty string.

## <a id="cssomstring-type"></a>3. CSSOMString

<a id="ref-for-idl-USVString"></a>

<a id="ref-for-idl-DOMString"></a>

Most strings in CSSOM interfaces use the <a id="cssomstring"></a>`CSSOMString` type. Each implementation chooses to define it as either <code><a href="https://heycam.github.io/webidl/#idl-USVString">USVString</a></code> or <code><a href="https://heycam.github.io/webidl/#idl-DOMString">DOMString</a></code>:

```webidl
typedef USVString CSSOMString;
```
Or, alternatively:

```webidl
typedef DOMString CSSOMString;
```
<a id="ref-for-surrogate"></a>

<a id="ref-for-idl-DOMString①"></a>

<a id="ref-for-idl-USVString①"></a>

> <strong data-conversion-semantic="note">Note</strong>
>
> The difference is only observable from web content when [surrogate](https://infra.spec.whatwg.org/#surrogate) code units are involved. <code><a href="https://heycam.github.io/webidl/#idl-DOMString">DOMString</a></code> would preserve them, whereas <code><a href="https://heycam.github.io/webidl/#idl-USVString">USVString</a></code> would replace them with U+FFFD REPLACEMENT CHARACTER.
>
> This choice effectively allows implementations to do this replacement, but does not require it.
>
> <a id="ref-for-idl-USVString②"></a>
>
> <a id="ref-for-surrogate①"></a>
>
> Using <code><a href="https://heycam.github.io/webidl/#idl-USVString">USVString</a></code> enables an implementation to use UTF-8 internally to represent strings in memory. Since well-formed UTF-8 specifically disallows [surrogate](https://infra.spec.whatwg.org/#surrogate) code points, it effectively requires this replacement.
>
> <a id="ref-for-code-unit"></a>
>
> On the other hand, implementations that internally represent strings as 16-bit [code units](https://infra.spec.whatwg.org/#code-unit) might prefer to avoid the cost of doing this replacement.

## <a id="media-queries"></a>4. Media Queries

<a id="ref-for-media-query"></a>

[Media queries](https://www.w3.org/TR/mediaqueries-5/#media-query) are defined by [\[MEDIAQUERIES\]](#biblio-mediaqueries). This section defines various concepts around <a id="ref-for-media-query①"></a>media queries, including their API and serialization form.

### <a id="parsing-media-queries"></a>4.1. Parsing Media Queries

<a id="ref-for-media-query-list"></a>

To <a id="parse-a-media-query-list"></a>parse a media query list for a given string <var>s</var> into a [media query list](https://www.w3.org/TR/mediaqueries-5/#media-query-list) is defined in the Media Queries specification. Return the list of media queries that the algorithm defined there gives.

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: A media query that ends up being "ignored" will turn into "`not all`".

<a id="ref-for-parse-a-media-query-list"></a>

To <a id="parse-a-media-query"></a>parse a media query for a given string <var>s</var> means to follow the [parse a media query list](#parse-a-media-query-list) steps and return null if more than one media query is returned or a media query if a single media query is returned.

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: Again, a media query that ends up being "ignored" will turn into "`not all`".

### <a id="serializing-media-queries"></a>4.2. Serializing Media Queries

To <a id="serialize-a-media-query-list"></a>serialize a media query list run these steps:

1.  <a id="ref-for-media-query-list①"></a>

    If the [media query list](https://www.w3.org/TR/mediaqueries-5/#media-query-list) is empty, then return the empty string.

2.  <a id="ref-for-serialize-a-comma-separated-list"></a>

    <a id="ref-for-media-query-list②"></a>

    <a id="ref-for-serialize-a-media-query"></a>

    [Serialize](#serialize-a-media-query) each media query in the list of media queries, in the same order as they appear in the [media query list](https://www.w3.org/TR/mediaqueries-5/#media-query-list), and then [serialize](#serialize-a-comma-separated-list) the list.

To <a id="serialize-a-media-query"></a>serialize a media query let <var>s</var> be the empty string, run the steps below:

1.  <a id="ref-for-media-query②"></a>

    If the [media query](https://www.w3.org/TR/mediaqueries-5/#media-query) is negated append "`not`", followed by a single SPACE (U+0020), to <var>s</var>.

2.  <a id="ref-for-ascii-lowercase"></a>

    <a id="ref-for-media-query③"></a>

    <a id="ref-for-media-type"></a>

    <a id="ref-for-serialize-an-identifier"></a>

    Let <var>type</var> be the [serialization as an identifier](#serialize-an-identifier) of the [media type](https://www.w3.org/TR/mediaqueries-5/#media-type) of the [media query](https://www.w3.org/TR/mediaqueries-5/#media-query), [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase).

3.  <a id="ref-for-media-feature"></a>

    <a id="ref-for-media-query④"></a>

    If the [media query](https://www.w3.org/TR/mediaqueries-5/#media-query) does not contain [media features](https://www.w3.org/TR/mediaqueries-5/#media-feature) append <var>type</var>, to <var>s</var>, then return <var>s</var>.

4.  If <var>type</var> is not "`all`" or if the media query is negated append <var>type</var>, followed by a single SPACE (U+0020), followed by "`and`", followed by a single SPACE (U+0020), to <var>s</var>.

5.  <a id="ref-for-media-feature①"></a>

    Then, for each [media feature](https://www.w3.org/TR/mediaqueries-5/#media-feature):

    1.  <a id="ref-for-ascii-lowercase①"></a>

        <a id="ref-for-media-feature②"></a>

        Append a "`(`" (U+0028), followed by the [media feature](https://www.w3.org/TR/mediaqueries-5/#media-feature) name, [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase), to <var>s</var>.

    2.  <a id="ref-for-serialize-a-media-feature-value"></a>

        If a value is given append a "`:`" (U+003A), followed by a single SPACE (U+0020), followed by the [serialized media feature value](#serialize-a-media-feature-value), to <var>s</var>.

    3.  Append a "`)`" (U+0029) to <var>s</var>.

    4.  <a id="ref-for-media-feature③"></a>

        If this is not the last [media feature](https://www.w3.org/TR/mediaqueries-5/#media-feature) append a single SPACE (U+0020), followed by "`and`", followed by a single SPACE (U+0020), to <var>s</var>.

6.  Return <var>s</var>.

>
> <a id="example-0d89c7fd"></a> Here are some examples of input (first column) and output (second column):
>

>
> **Input**

> ```

## <a id="selectors"></a>5. Selectors

Selectors are defined in the Selectors specification. This section mainly defines how to serialize them.

### <a id="parsing-selectors"></a>5.1. Parsing Selectors

To <a id="parse-a-group-of-selectors"></a>parse a group of selectors means to parse the value using the `selectors_group` production defined in the Selectors specification and return either a group of selectors if parsing did not fail or null if parsing did fail.

### <a id="serializing-selectors"></a>5.2. Serializing Selectors

<a id="ref-for-serialize-a-selector"></a>

<a id="ref-for-serialize-a-comma-separated-list①"></a>

To <a id="serialize-a-group-of-selectors"></a>serialize a group of selectors [serialize](#serialize-a-selector) each selector in the group of selectors and then [serialize](#serialize-a-comma-separated-list) a comma-separated list of these serializations.

To <a id="serialize-a-selector"></a>serialize a selector let <var>s</var> be the empty string, run the steps below for each part of the chain of the selector, and finally return <var>s</var>:

1.  <a id="ref-for-serialize-a-simple-selector"></a>

    <a id="ref-for-universal-selector"></a>

    <a id="ref-for-compound"></a>

    <a id="ref-for-simple"></a>

    If there is only one [simple selector](https://www.w3.org/TR/selectors-4/#simple) in the [compound selectors](https://www.w3.org/TR/selectors-4/#compound) which is a [universal selector](https://www.w3.org/TR/selectors-4/#universal-selector), append the result of [serializing](#serialize-a-simple-selector) the <a id="ref-for-universal-selector①"></a>universal selector to <var>s</var>.

2.  <a id="ref-for-serialize-a-simple-selector①"></a>

    <a id="ref-for-default-namespace"></a>

    <a id="ref-for-namespace-prefix"></a>

    <a id="ref-for-compound①"></a>

    <a id="ref-for-simple①"></a>

    Otherwise, for each [simple selector](https://www.w3.org/TR/selectors-4/#simple) in the [compound selectors](https://www.w3.org/TR/selectors-4/#compound) that is not a universal selector of which the [namespace prefix](https://www.w3.org/TR/css-namespaces-3/#namespace-prefix) maps to a namespace that is not the [default namespace](https://www.w3.org/TR/css-namespaces-3/#default-namespace) [serialize](#serialize-a-simple-selector) the <a id="ref-for-simple②"></a>simple selector and append the result to <var>s</var>.

3.  If this is not the last part of the chain of the selector append a single SPACE (U+0020), followed by the combinator "`>`", "`+`", "`~`", "`>>`", "`||`", as appropriate, followed by another single SPACE (U+0020) if the combinator was not whitespace, to <var>s</var>.

4.  If this is the last part of the chain of the selector and there is a pseudo-element, append "`::`" followed by the name of the pseudo-element, to <var>s</var>.

To <a id="serialize-a-simple-selector"></a>serialize a simple selector let <var>s</var> be the empty string, run the steps below, and finally return <var>s</var>:

type selector  
universal selector  
1.  <a id="ref-for-serialize-an-identifier①"></a>

    <a id="ref-for-default-namespace①"></a>

    <a id="ref-for-namespace-prefix①"></a>

    If the [namespace prefix](https://www.w3.org/TR/css-namespaces-3/#namespace-prefix) maps to a namespace that is not the [default namespace](https://www.w3.org/TR/css-namespaces-3/#default-namespace) and is not the null namespace (not in a namespace) append the [serialization](#serialize-an-identifier) of the <a id="ref-for-namespace-prefix②"></a>namespace prefix as an identifier, followed by a "`|`" (U+007C) to <var>s</var>.

2.  <a id="ref-for-namespace-prefix③"></a>

    If the [namespace prefix](https://www.w3.org/TR/css-namespaces-3/#namespace-prefix) maps to a namespace that is the null namespace (not in a namespace) append "`|`" (U+007C) to <var>s</var>.

3.  <a id="ref-for-serialize-an-identifier②"></a>

    If this is a type selector append the [serialization](#serialize-an-identifier) of the element name as an identifier to <var>s</var>.

4.  If this is a universal selector append "`*`" (U+002A) to <var>s</var>.

attribute selector  
1.  Append "`[`" (U+005B) to <var>s</var>.

2.  <a id="ref-for-serialize-an-identifier③"></a>

    <a id="ref-for-namespace-prefix④"></a>

    If the [namespace prefix](https://www.w3.org/TR/css-namespaces-3/#namespace-prefix) maps to a namespace that is not the null namespace (not in a namespace) append the [serialization](#serialize-an-identifier) of the <a id="ref-for-namespace-prefix⑤"></a>namespace prefix as an identifier, followed by a "`|`" (U+007C) to <var>s</var>.

3.  <a id="ref-for-serialize-an-identifier④"></a>

    Append the [serialization](#serialize-an-identifier) of the attribute name as an identifier to <var>s</var>.

4.  <a id="ref-for-serialize-a-string②"></a>

    If there is an attribute value specified, append "`=`", "`~=`", "`|=`", "`^=`", "`$=`", or "`*=`" as appropriate (depending on the type of attribute selector), followed by the [serialization](#serialize-a-string) of the attribute value as a string, to <var>s</var>.

5.  If the attribute selector has the case-sensitivity flag present, append "`  i `" (U+0020 U+0069) to <var>s</var>.

6.  Append "`]`" (U+005D) to <var>s</var>.

class selector  
<a id="ref-for-serialize-an-identifier⑤"></a>

Append a "`.`" (U+002E), followed by the [serialization](#serialize-an-identifier) of the class name as an identifier to <var>s</var>.

ID selector  
<a id="ref-for-serialize-an-identifier⑥"></a>

Append a "`#`" (U+0023), followed by the [serialization](#serialize-an-identifier) of the ID as an identifier to <var>s</var>.

pseudo-class  
If the pseudo-class does not accept arguments append "`:`" (U+003A), followed by the name of the pseudo-class, to <var>s</var>.

Otherwise, append "`:`" (U+003A), followed by the name of the pseudo-class, followed by "`(`" (U+0028), followed by the value of the pseudo-class argument(s) determined as per below, followed by "`)`" (U+0029), to <var>s</var>.

`:lang()`  
<a id="ref-for-serialize-a-string③"></a>

<a id="ref-for-serialize-a-comma-separated-list②"></a>

The [serialization of a comma-separated list](#serialize-a-comma-separated-list) of each argument’s [serialization as a string](#serialize-a-string), preserving relative order.

`:nth-child()`  
`:nth-last-child()`  
`:nth-of-type()`  
`:nth-last-of-type()`  
<a id="ref-for-serialize-an-anb-value"></a>

The result of serializing the value using the rules to [serialize an \<an+b\> value](https://www.w3.org/TR/css-syntax-3/#serialize-an-anb-value).

`:not()`  
<a id="ref-for-serialize-a-group-of-selectors"></a>

The result of serializing the value using the rules for [serializing a group of selectors](#serialize-a-group-of-selectors).

    Set <var>sheet</var>’s [owner node](https://www.w3.org/TR/cssom-1/#concept-css-style-sheet-owner-node) to null.

    <a id="ref-for-concept-css-style-sheet-media"></a>

    <a id="ref-for-create-a-medialist-object"></a>

    <a id="ref-for-dom-cssstylesheetinit-media"></a>

    If the <code><a href="#dom-cssstylesheetinit-media">media</a></code> attribute of <var>options</var> is a string, [create a MediaList object](#create-a-medialist-object) from the string and assign it as <var>sheet</var>’s [media](https://www.w3.org/TR/cssom-1/#concept-css-style-sheet-media). <a id="concept-css-style-sheet-origin-clean-flag"></a>origin-clean flag  
<a id="ref-for-concept-css-style-sheet-css-rules"></a>

Specified when created. Either set or unset. If it is set, the API allows reading and modifying of the [CSS rules](#concept-css-style-sheet-css-rules).

<a id="concept-css-style-sheet-constructed-flag"></a>constructed flag  
Specified when created. Either set or unset. Unset by default. Signifies whether this stylesheet was created by invoking the IDL-defined constructor.

<a id="concept-css-style-sheet-disallow-modification-flag"></a>disallow modification flag  
Either set or unset. Unset by default. If set, modification of the stylesheet’s rules is not allowed.

<a id="concept-css-style-sheet-constructor-document"></a>constructor document  
<a id="ref-for-concept-css-style-sheet-constructed-flag①"></a>

<a id="ref-for-document"></a>

Specified when created. The <code><a href="https://dom.spec.whatwg.org/#document">Document</a></code> a constructed stylesheet is associated with. Null by default. Only non-null for stylesheets that have [constructed flag](#concept-css-style-sheet-constructed-flag) set.

<a id="concept-css-style-sheet-stylesheet-base-url"></a>stylesheet base URL  
<a id="ref-for-concept-css-style-sheet-constructed-flag②"></a>

The base URL to use when resolving relative URLs in the stylesheet. Null by default. Only non-null for stylesheets that have [constructed flag](#concept-css-style-sheet-constructed-flag) set.

    >

For example, invoking the <code><a href="#dom-cssstylesheet-insertrule">insertRule()</a></code> or <code><a href="#dom-cssstylesheet-deleterule">deleteRule()</a></code> methods can result in mutations reflected in the returned object.

The <a id="dom-cssstylesheet-insertrule"></a><code>insertRule(<var>rule</var>, <var>index</var>)</code> method must run the following steps:

1.  <a id="ref-for-securityerror①"></a>

5.  <a id="ref-for-idl-DOMException①"></a>

6.  <a id="ref-for-concept-css-style-sheet-css-rules②"></a>

1.  <a id="ref-for-securityerror②"></a>

    <a id="ref-for-concept-css-style-sheet-disallow-modification-flag①"></a>

3.  <a id="ref-for-concept-css-style-sheet-css-rules③"></a>

The <a id="dom-cssstylesheet-replace"></a><code>replace(<a href="#concept-css-rule-text">text</a>)</code> method must run the following steps:

1.  Let <var>promise</var> be a promise.

2.  <a id="ref-for-idl-DOMException③"></a>

    <a id="ref-for-notallowederror②"></a>

    <a id="ref-for-concept-css-style-sheet-constructed-flag④"></a>

3.  <a id="ref-for-concept-css-style-sheet-disallow-modification-flag③"></a>

4.  <a id="ref-for-in-parallel"></a>

    [In parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel), do these steps:

    1.  <a id="ref-for-parse-a-list-of-rules"></a>

    2.  <a id="ref-for-remove-a-css-rule①"></a>

    3.  <a id="ref-for-concept-css-style-sheet-css-rules④"></a>

        Set <var>sheet</var>’s [CSS rules](#concept-css-style-sheet-css-rules) to <var>rules</var>.

    4.  <a id="ref-for-concept-css-style-sheet-disallow-modification-flag④"></a>

        Unset <var>sheet</var>’s [disallow modification flag](#concept-css-style-sheet-disallow-modification-flag).

    5.  Resolve <var>promise</var> with <var>sheet</var>.

5.  Return <var>promise</var>.

1.  <a id="ref-for-css-style-sheet②②"></a>

### <a id="style-sheet-association"></a>6.3. Style Sheet Association

<a id="ref-for-concept-css-style-sheet-owner-node⑧"></a>

<a id="ref-for-css-style-sheet③⑨"></a>

<a id="ref-for-dt-xml-stylesheet"></a>

This section defines the interface an [owner node](#concept-css-style-sheet-owner-node) of a [CSS style sheet](#css-style-sheet) has to implement and defines the requirements for [xml-stylesheet processing instructions](https://www.w3.org/TR/xml-stylesheet/#dt-xml-stylesheet) and HTTP `Link` headers when the link relation type is an [ASCII case-insensitive](https://html.spec.whatwg.org/multipage/infrastructure.html#ascii-case-insensitive) match for "`stylesheet`".

#### <a id="fetching-css-style-sheets"></a>6.3.1. Fetching CSS style sheets

<a id="ref-for-concept-request"></a>

To <a id="fetch-a-css-style-sheet"></a>fetch a CSS style sheet with parsed URL <var>parsed URL</var>, referrer <var>referrer</var>, document <var>document</var>, optionally a set of parameters <var>parameters</var> (used as input to creating a [request](https://fetch.spec.whatwg.org/#concept-request)), follow these steps:

1.  <a id="ref-for-concept-origin"></a>

    Let <var>origin</var> be <var>document</var>’s [origin](https://html.spec.whatwg.org/multipage/origin.html#concept-origin).

2.  <a id="ref-for-concept-request-referrer"></a>

    <a id="ref-for-concept-request-origin"></a>

    <a id="ref-for-concept-request-url"></a>

    <a id="ref-for-concept-request①"></a>

    Let <var>request</var> be a new [request](https://fetch.spec.whatwg.org/#concept-request), with the [url](https://fetch.spec.whatwg.org/#concept-request-url) <var>parsed URL</var>, [origin](https://fetch.spec.whatwg.org/#concept-request-origin) <var>origin</var>, [referrer](https://fetch.spec.whatwg.org/#concept-request-referrer) <var>referrer</var>, and if specified the set of parameters <var>parameters</var>.

3.  <a id="ref-for-concept-fetch"></a>

    Let <var>response</var> be the result of [fetching](https://fetch.spec.whatwg.org/#concept-fetch) <var>request</var>.

4.  Wait until <var>response</var> is available.

5.  <a id="ref-for-concept-network-error"></a>

    If <var>response</var> is a [network error](https://fetch.spec.whatwg.org/#concept-network-error), return an error.

6.  <a id="ref-for-supported-styling-language"></a>

    <a id="ref-for-content-type"></a>

    <a id="ref-for-cors-same-origin"></a>

    <a id="ref-for-concept-document-quirks"></a>

    If <var>document</var> is in [quirks mode](https://dom.spec.whatwg.org/#concept-document-quirks), <var>response</var> is [CORS-same-origin](https://html.spec.whatwg.org/multipage/urls-and-fetching.html#cors-same-origin) and the [Content-Type metadata](https://html.spec.whatwg.org/multipage/infrastructure.html#content-type) of <var>response</var> is not a [supported styling language](#supported-styling-language) change the <a id="ref-for-content-type①"></a>Content-Type metadata of <var>response</var> to `text/css`.

7.  <a id="ref-for-supported-styling-language①"></a>

    If <var>response</var> is not in a [supported styling language](#supported-styling-language) return an error.

8.  Return <var>response</var>.

### <a id="css-rules"></a>6.4. CSS Rules

<a id="ref-for-css-rule①"></a>

<a id="ref-for-cssrule①"></a>

A <a id="css-rule"></a>CSS rule is an abstract concept that denotes a rule as defined by the CSS specification. A [CSS rule](#css-rule) is represented as an object that implements a subclass of the <code><a href="#cssrule">CSSRule</a></code> interface, and which has the following associated state items:

<a id="concept-css-rule-type"></a>type  
A non-negative integer associated with a particular type of rule. This item is initialized when a rule is created and cannot change.

<a id="concept-css-rule-text"></a>text  
A text representation of the rule suitable for direct use in a style sheet. This item is initialized when a rule is created and can be changed.

<a id="concept-css-rule-parent-css-rule"></a>parent CSS rule  
<a id="ref-for-css-rule②"></a>

A reference to an enclosing [CSS rule](#css-rule) or null. If the rule has an enclosing rule when it is created, then this item is initialized to the enclosing rule; otherwise it is null. It can be changed to null.

<a id="concept-css-rule-parent-css-style-sheet"></a>parent CSS style sheet  
<a id="ref-for-css-style-sheet④②"></a>

A reference to a parent [CSS style sheet](#css-style-sheet) or null. This item is initialized to reference an associated style sheet when the rule is created. It can be changed to null.

<a id="concept-css-rule-child-css-rules"></a>child CSS rules  
<a id="ref-for-css-rule③"></a>

A list of child [CSS rules](#css-rule). The list can be mutated.

<a id="ref-for-css-rule④"></a>

<a id="ref-for-concept-css-rule-type"></a>

In addition to the above state, each [CSS rule](#css-rule) may be associated with other state in accordance with its [type](#concept-css-rule-type).

To <a id="parse-a-css-rule"></a>parse a CSS rule from a string <var>string</var>, run the following steps:

1.  <a id="ref-for-parse-a-rule①"></a>

    Let <var>rule</var> be the return value of invoking [parse a rule](https://www.w3.org/TR/css-syntax-3/#parse-a-rule) with <var>string</var>.

2.  If <var>rule</var> is a syntax error, return <var>rule</var>.

3.  Let <var>parsed rule</var> be the result of parsing <var>rule</var> according to the appropriate CSS specifications, dropping parts that are said to be ignored. If the whole style rule is dropped, return a syntax error.

4.  Return <var>parsed rule</var>.

        2.  Append <var>rule</var> to <var>s</var>.
    3.  Append a newline followed by RIGHT CURLY BRACKET (U+007D) to <var>s</var>.

2.  <a id="ref-for-indexsizeerror"></a>

[\[CSS21\]](#biblio-css21)

    > <strong data-conversion-semantic="note">Note</strong>
    >
    > Note: For example, a CSS style sheet cannot contain an `@import` at-rule after a style rule.

6.  <a id="ref-for-invalidstateerror"></a>

Unset by default. Set when the [CSS declaration block](#css-declaration-block) is updating the [owner node](#cssstyledeclaration-owner-node)’s `style` attribute.

To <a id="parse-a-css-declaration-block"></a>parse a CSS declaration block from a string <var>string</var>, follow these steps:

1.  <a id="ref-for-parse-a-list-of-declarations"></a>

    Let <var>declarations</var> be the return value of invoking [parse a list of declarations](https://www.w3.org/TR/css-syntax-3/#parse-a-list-of-declarations) with <var>string</var>.

2.  Let <var>parsed declarations</var> be a new empty list.

3.  For each item <var>declaration</var> in <var>declarations</var>, follow these substeps:
    1.  Let <var>parsed declaration</var> be the result of parsing <var>declaration</var> according to the appropriate CSS specifications, dropping parts that are said to be ignored. If the whole declaration is dropped, let <var>parsed declaration</var> be null.
    2.  If <var>parsed declaration</var> is not null, append it to <var>parsed declarations</var>.

4.  Return <var>parsed declarations</var>.

To <a id="serialize-a-css-declaration"></a>serialize a CSS declaration with property name <var>property</var>, value <var>value</var> and optionally an <i>important</i> flag set, follow these steps:

1.  Let <var>s</var> be the empty string.
2.  Append <var>property</var> to <var>s</var>.
3.  Append "` :  `" (U+003A U+0020) to <var>s</var>.
4.  Append <var>value</var> to <var>s</var>.
5.  If the <i>important</i> flag is set, append "`  !important `" (U+0020 U+0021 U+0069 U+006D U+0070 U+006F U+0072 U+0074 U+0061 U+006E U+0074) to <var>s</var>.
6.  Append "`;`" (U+003B) to <var>s</var>.
7.  Return <var>s</var>.

To <a id="serialize-a-css-declaration-block"></a>serialize a CSS declaration block <var>declaration block</var> means to run the steps below:

1.  Let <var>list</var> be an empty array.

2.  Let <var>already serialized</var> be an empty array.

3.  <a id="ref-for-cssstyledeclaration-declarations③"></a>

    <a id="ref-for-css-declaration③"></a>

    <i>Declaration loop</i>: For each [CSS declaration](#css-declaration) <var>declaration</var> in <var>declaration block</var>’s [declarations](#cssstyledeclaration-declarations), follow these substeps:

    1.  <a id="ref-for-css-declaration-property-name①"></a>

        Let <var>property</var> be <var>declaration</var>’s [property name](#css-declaration-property-name).

    2.  If <var>property</var> is in <var>already serialized</var>, continue with the steps labeled <i>declaration loop</i>.

    3.  <a id="ref-for-concept-shorthands-preferred-order"></a>

        If <var>property</var> maps to one or more shorthand properties, let <var>shorthands</var> be an array of those shorthand properties, in [preferred order](#concept-shorthands-preferred-order).

    4.  <i>Shorthand loop</i>: For each <var>shorthand</var> in <var>shorthands</var>, follow these substeps:
        1.  <a id="ref-for-css-declaration-property-name②"></a>

            <a id="ref-for-cssstyledeclaration-declarations④"></a>

            <a id="ref-for-css-declaration④"></a>

            Let <var>longhands</var> be an array consisting of all [CSS declarations](#css-declaration) in <var>declaration block</var>’s [declarations](#cssstyledeclaration-declarations) that that are not in <var>already serialized</var> and have a [property name](#css-declaration-property-name) that maps to one of the shorthand properties in <var>shorthands</var>.

        2.  If all properties that map to <var>shorthand</var> are not present in <var>longhands</var>, continue with the steps labeled <i>shorthand loop</i>.

        3.  Let <var>current longhands</var> be an empty array.

        4.  <a id="ref-for-css-declaration-property-name③"></a>

            <a id="ref-for-css-declaration⑤"></a>

            Append all [CSS declarations](#css-declaration) in <var>longhands</var> that have a [property name](#css-declaration-property-name) that maps to <var>shorthand</var> to <var>current longhands</var>.

        5.  <a id="ref-for-css-declaration-important-flag"></a>

            <a id="ref-for-css-declaration⑥"></a>

            If there is one or more [CSS declarations](#css-declaration) in <var>current longhands</var> have their [important flag](#css-declaration-important-flag) set and one or more with it unset, continue with the steps labeled <i>shorthand loop</i>.

        6.  <a id="ref-for-mapping-logic"></a>

            <a id="ref-for-logical-property-group"></a>

            If there’s any declaration in <var>declaration block</var> in between the first and the last longhand in <var>current longhands</var> which belongs to the same [logical property group](https://www.w3.org/TR/css-logical-1/#logical-property-group), but has a different [mapping logic](https://www.w3.org/TR/css-logical-1/#mapping-logic) as any of the longhands in <var>current longhands</var>, and is not in <var>current longhands</var>, continue with the steps labeled <i>shorthand loop</i>.

        7.  <a id="ref-for-serialize-a-css-value"></a>

            Let <var>value</var> be the result of invoking [serialize a CSS value](#serialize-a-css-value) of <var>current longhands</var>.

        8.  If <var>value</var> is the empty string, continue with the steps labeled <i>shorthand loop</i>.

        9.  <a id="ref-for-css-declaration-important-flag①"></a>

            <a id="ref-for-css-declaration⑦"></a>

            <a id="ref-for-serialize-a-css-declaration"></a>

            Let <var>serialized declaration</var> be the result of invoking [serialize a CSS declaration](#serialize-a-css-declaration) with property name <var>shorthand</var>, value <var>value</var>, and the <i>important</i> flag set if the [CSS declarations](#css-declaration) in <var>current longhands</var> have their [important flag](#css-declaration-important-flag) set.

        10. Append <var>serialized declaration</var> to <var>list</var>.

        11. Append the property names of all items of <var>current longhands</var> to <var>already serialized</var>.

        12. Continue with the steps labeled <i>declaration loop</i>.

    5.  <a id="ref-for-serialize-a-css-value①"></a>

        Let <var>value</var> be the result of invoking [serialize a CSS value](#serialize-a-css-value) of <var>declaration</var>.

    6.  <a id="ref-for-css-declaration-important-flag②"></a>

        <a id="ref-for-serialize-a-css-declaration①"></a>

        Let <var>serialized declaration</var> be the result of invoking [serialize a CSS declaration](#serialize-a-css-declaration) with property name <var>property</var>, value <var>value</var>, and the <i>important</i> flag set if <var>declaration</var> has its [important flag](#css-declaration-important-flag) set.

    7.  Append <var>serialized declaration</var> to <var>list</var>.

    8.  Append <var>property</var> to <var>already serialized</var>.

4.  Return <var>list</var> joined with "`   `" (U+0020).

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: The serialization of an empty CSS declaration block is the empty string.

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: The serialization of a non-empty CSS declaration block does not include any surrounding whitespace, i.e., no whitespace appears before the first property name and no whitespace appears after the final semicolon delimiter that follows the last property value.

<a id="ref-for-concept-element-attributes-change-ext"></a>

<a id="ref-for-cssstyledeclaration-owner-node④"></a>

A [CSS declaration block](#css-declaration-block) has these [attribute change steps](https://dom.spec.whatwg.org/#concept-element-attributes-change-ext) for its [owner node](#cssstyledeclaration-owner-node) with <var>localName</var>, <var>value</var>, and <var>namespace</var>:

1.  <a id="ref-for-cssstyledeclaration-computed-flag③"></a>

    If the [computed flag](#cssstyledeclaration-computed-flag) is set, then return.

2.  <a id="ref-for-cssstyledeclaration-updating-flag"></a>

4.  <a id="ref-for-cssstyledeclaration-declarations⑤"></a>

5.  <a id="ref-for-parse-a-css-declaration-block"></a>

    <a id="ref-for-cssstyledeclaration-declarations⑥"></a>

<a id="ref-for-css-declaration-block⑥"></a>

When a [CSS declaration block](#css-declaration-block) object is created, then:

1.  <a id="ref-for-cssstyledeclaration-owner-node⑤"></a>

    Let <var>owner node</var> be the [owner node](#cssstyledeclaration-owner-node).

2.  <a id="ref-for-cssstyledeclaration-computed-flag④"></a>

    If <var>owner node</var> is null, or the [computed flag](#cssstyledeclaration-computed-flag) is set, then return.

3.  <a id="ref-for-concept-element-attributes-get-by-namespace"></a>

    Let <var>value</var> be the result of [getting an attribute](https://dom.spec.whatwg.org/#concept-element-attributes-get-by-namespace) given null, "`style`", and <var>owner node</var>.

4.  <a id="ref-for-parse-a-css-declaration-block①"></a>

    <a id="ref-for-cssstyledeclaration-declarations⑦"></a>

    If <var>value</var> is not null, let the [declarations](#cssstyledeclaration-declarations) be the result of [parse a CSS declaration block](#parse-a-css-declaration-block) from a string <var>value</var>.

To <a id="update-style-attribute-for"></a>update style attribute for <var>declaration block</var> means to run the steps below:

1.  <a id="ref-for-cssstyledeclaration-computed-flag⑤"></a>

    Assert: <var>declaration block</var>’s [computed flag](#cssstyledeclaration-computed-flag) is unset.

2.  <a id="ref-for-cssstyledeclaration-owner-node⑥"></a>

    Let <var>owner node</var> be <var>declaration block</var>’s [owner node](#cssstyledeclaration-owner-node).

3.  If <var>owner node</var> is null, then return.

4.  <a id="ref-for-cssstyledeclaration-updating-flag①"></a>

    Set <var>declaration block</var>’s [updating flag](#cssstyledeclaration-updating-flag).

5.  <a id="ref-for-serialize-a-css-declaration-block②"></a>

    <a id="ref-for-concept-element-attributes-set-value"></a>

    [Set an attribute value](https://dom.spec.whatwg.org/#concept-element-attributes-set-value) for <var>owner node</var> using "`style`" and the result of [serializing](#serialize-a-css-declaration-block) <var>declaration block</var>.

6.  <a id="ref-for-cssstyledeclaration-updating-flag②"></a>

    Unset <var>declaration block</var>’s [updating flag](#cssstyledeclaration-updating-flag).

The <a id="concept-shorthands-preferred-order"></a>preferred order of a list of shorthand properties <var>shorthands</var> is as follows:

1.  Order <var>shorthands</var> lexicographically.
2.  Move all items in <var>shorthands</var> that begin with "`-`" (U+002D) last in the list, retaining their relative order.
3.  Move all items in <var>shorthands</var> that begin with "`-`" (U+002D) but do not begin with "`-webkit-`" last in the list, retaining their relative order.
4.  Order <var>shorthands</var> by the number of longhand properties that map to it, with the greatest number first.

The <a id="dom-cssstyledeclaration-getpropertyvalue"></a><code>getPropertyValue(<var>property</var>)</code> method must run these steps:

1.  <a id="ref-for-custom-property①"></a>

    If <var>property</var> is not a [custom property](https://www.w3.org/TR/css-variables-1/#custom-property), follow these substeps:

    1.  <a id="ref-for-ascii-lowercase②"></a>

        Let <var>property</var> be <var>property</var> [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase).

    2.  If <var>property</var> is a shorthand property, then follow these substeps:
        1.  Let <var>list</var> be a new empty array.

        2.  For each longhand property <var>longhand</var> that <var>property</var> maps to, in canonical order, follow these substeps:
            1.  <a id="ref-for-cssstyledeclaration-declarations①③"></a>

                <a id="ref-for-css-declaration①②"></a>

                <a id="ref-for-css-declaration-property-name⑤"></a>

                If <var>longhand</var> is a case-sensitive match for a [property name](#css-declaration-property-name) of a [CSS declaration](#css-declaration) in the [declarations](#cssstyledeclaration-declarations), let <var>declaration</var> be that <a id="ref-for-css-declaration①③"></a>CSS declaration, or null otherwise.

            2.  If <var>declaration</var> is null, then return the empty string.

            3.  Append the <var>declaration</var> to <var>list</var>.

        3.  <a id="ref-for-serialize-a-css-value②"></a>

            <a id="ref-for-css-declaration-important-flag③"></a>

            If [important flags](#css-declaration-important-flag) of all declarations in <var>list</var> are same, then return the [serialization](#serialize-a-css-value) of <var>list</var>.

        4.  Return the empty string.

2.  <a id="ref-for-serialize-a-css-value③"></a>

    <a id="ref-for-cssstyledeclaration-declarations①④"></a>

    <a id="ref-for-css-declaration①④"></a>

    <a id="ref-for-css-declaration-property-name⑥"></a>

    If <var>property</var> is a case-sensitive match for a [property name](#css-declaration-property-name) of a [CSS declaration](#css-declaration) in the [declarations](#cssstyledeclaration-declarations), then return the result of invoking [serialize a CSS value](#serialize-a-css-value) of that declaration.

3.  Return the empty string.

The <a id="dom-cssstyledeclaration-getpropertypriority"></a><code>getPropertyPriority(<var>property</var>)</code> method must run these steps:

1.  <a id="ref-for-custom-property②"></a>

    If <var>property</var> is not a [custom property](https://www.w3.org/TR/css-variables-1/#custom-property), follow these substeps:

    1.  <a id="ref-for-ascii-lowercase③"></a>

        Let <var>property</var> be <var>property</var> [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase).

    2.  If <var>property</var> is a shorthand property, follow these substeps:
        1.  Let <var>list</var> be a new array.

        2.  <a id="ref-for-dom-cssstyledeclaration-getpropertypriority①"></a>

            For each longhand property <var>longhand</var> that <var>property</var> maps to, append the result of invoking <code><a href="#dom-cssstyledeclaration-getpropertypriority">getPropertyPriority()</a></code> with <var>longhand</var> as argument to <var>list</var>.

        3.  If all items in <var>list</var> are the string "`important`", then return the string "`important`".

2.  <a id="ref-for-css-declaration-important-flag④"></a>

    <a id="ref-for-cssstyledeclaration-declarations①⑤"></a>

    <a id="ref-for-css-declaration①⑤"></a>

    <a id="ref-for-css-declaration-property-name⑦"></a>

    If <var>property</var> is a case-sensitive match for a [property name](#css-declaration-property-name) of a [CSS declaration](#css-declaration) in the [declarations](#cssstyledeclaration-declarations) that has the [important flag](#css-declaration-important-flag) set, return the string "`important`".

3.  Return the empty string.

> <strong data-conversion-semantic="example">Example</strong>
>
> <a id="example-666534ab"></a>E.g. for `background-color:lime !IMPORTANT` the return value would be "`important`".

The <a id="dom-cssstyledeclaration-setproperty"></a><code>setProperty(<var>property</var>, <var>value</var>, <var>priority</var>)</code> method must run these steps:

1.  <a id="ref-for-nomodificationallowederror①"></a>

    <a id="ref-for-dfn-throw①①"></a>

    <a id="ref-for-cssstyledeclaration-computed-flag⑧"></a>

    If the [computed flag](#cssstyledeclaration-computed-flag) is set, then [throw](http://heycam.github.io/webidl/#dfn-throw) a <code><a href="https://heycam.github.io/webidl/#nomodificationallowederror">NoModificationAllowedError</a></code> exception.

2.  <a id="ref-for-custom-property③"></a>

    If <var>property</var> is not a [custom property](https://www.w3.org/TR/css-variables-1/#custom-property), follow these substeps:

    1.  <a id="ref-for-ascii-lowercase④"></a>

        Let <var>property</var> be <var>property</var> [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase).

    2.  <a id="ref-for-supported-css-property①"></a>

        If <var>property</var> is not a case-sensitive match for a [supported CSS property](#supported-css-property), then return.

3.  <a id="ref-for-dom-cssstyledeclaration-removeproperty①"></a>

    If <var>value</var> is the empty string, invoke <code><a href="#dom-cssstyledeclaration-removeproperty">removeProperty()</a></code> with <var>property</var> as argument and return.

4.  <a id="ref-for-ascii-case-insensitive④"></a>

    If <var>priority</var> is not the empty string and is not an [ASCII case-insensitive](https://html.spec.whatwg.org/multipage/infrastructure.html#ascii-case-insensitive) match for the string "`important`", then return.

5.  <a id="ref-for-parse-a-css-value"></a>

    Let <var>component value list</var> be the result of [parsing](#parse-a-css-value) <var>value</var> for property <var>property</var>.

    > <strong data-conversion-semantic="note">Note</strong>
    >
    > Note: <var>value</var> can not include "`!important`".

6.  If <var>component value list</var> is null, then return.

7.  Let <var>updated</var> be false.

8.  If <var>property</var> is a shorthand property, then for each longhand property <var>longhand</var> that <var>property</var> maps to, in canonical order, follow these substeps:
    1.  <a id="ref-for-cssstyledeclaration-declarations①⑥"></a>

        <a id="ref-for-set-a-css-declaration"></a>

        Let <var>longhand result</var> be the result of [set the CSS declaration](#set-a-css-declaration) <var>longhand</var> with the appropriate value(s) from <var>component value list</var>, with the <i>important</i> flag set if <var>priority</var> is not the empty string, and unset otherwise, and with the list of declarations being the [declarations](#cssstyledeclaration-declarations).

    2.  If <var>longhand result</var> is true, let <var>updated</var> be true.

9.  <a id="ref-for-cssstyledeclaration-declarations①⑦"></a>

    <a id="ref-for-set-a-css-declaration①"></a>

    Otherwise, let <var>updated</var> be the result of [set the CSS declaration](#set-a-css-declaration) <var>property</var> with value <var>component value list</var>, with the <i>important</i> flag set if <var>priority</var> is not the empty string, and unset otherwise, and with the list of declarations being the [declarations](#cssstyledeclaration-declarations).

10. <a id="ref-for-css-declaration-block⑨"></a>

    <a id="ref-for-update-style-attribute-for①"></a>

    If <var>updated</var> is true, [update style attribute for](#update-style-attribute-for) the [CSS declaration block](#css-declaration-block).

To <a id="set-a-css-declaration"></a>set a CSS declaration <var>property</var> with a value <var>component value list</var> and optionally with an <i>important</i> flag set, in a list of declarations <var>declarations</var>, the user agent must ensure the following constraints hold after its steps:

- <a id="ref-for-css-declaration-property-name⑧"></a>

  <a id="ref-for-css-declaration①⑥"></a>

  Exactly one [CSS declaration](#css-declaration) whose [property name](#css-declaration-property-name) is a case-sensitive match of <var>property</var> must exist in <var>declarations</var>. Such declaration is referenced as the <var>target declaration</var> below.

- <a id="ref-for-unset"></a>

  <a id="ref-for-set"></a>

  <a id="ref-for-css-declaration-important-flag⑤"></a>

  The <var>target declaration</var> must have value being <var>component value list</var>, and <var>target declaration</var>’s [important flag](#css-declaration-important-flag) must be [set](#set) if <i>important</i> flag is set, and [unset](#unset) otherwise.

- <a id="ref-for-css-declaration①⑦"></a>

  Any [CSS declaration](#css-declaration) which is not the <var>target declaration</var> must not be changed, inserted, or removed from <var>declarations</var>.

- <a id="ref-for-mapping-logic①"></a>

  <a id="ref-for-logical-property-group①"></a>

  <a id="ref-for-css-declaration-property-name⑨"></a>

  <a id="ref-for-css-declaration①⑧"></a>

  If there are [CSS declarations](#css-declaration) in <var>declarations</var> whose [property name](#css-declaration-property-name) is in the same [logical property group](https://www.w3.org/TR/css-logical-1/#logical-property-group) as <var>property</var>, but has a different [mapping logic](https://www.w3.org/TR/css-logical-1/#mapping-logic), <var>target declaration</var> must be at an index after all of those <a id="ref-for-css-declaration①⑨"></a>CSS declarations.

- The steps must return true if the serialization of <var>declarations</var> was changed as result of the steps. It may return false otherwise.

> <strong data-conversion-semantic="issue">Issue</strong>
>
> <a id="issue-aaf411cc"></a> Should we add something like "Any observable side effect must not be made outside <var>declarations</var>"? The current constraints sound like a hole for undefined behavior.

<a id="ref-for-set-a-css-declaration②"></a>

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: The steps of [set a CSS declaration](#set-a-css-declaration) are not defined in this level of CSSOM. User agents may use different algorithms as long as the constraints above hold.

> <strong data-conversion-semantic="example">Example</strong>
>
> <a id="example-a40690cb"></a> The simplest way to conform with the constraints would be to always remove any existing declaration matching <var>property</var>, and append the new declaration to the end. But based on implementation feedback, this approach would likely regress performance.
>
> Another possible algorithm is:
>
> 1.  <a id="ref-for-css-declaration②⓪"></a>
>
>     <a id="ref-for-css-declaration-property-name①⓪"></a>
>
>     If <var>property</var> is a case-sensitive match for a [property name](#css-declaration-property-name) of a [CSS declaration](#css-declaration) in <var>declarations</var>, follow these substeps:
>
>     1.  <a id="ref-for-css-declaration②①"></a>
>
>         Let <var>target declaration</var> be such [CSS declaration](#css-declaration).
>
>     2.  Let <var>needs append</var> be false.
>
>     3.  <a id="ref-for-list-iterate"></a>
>
>         [For each](https://infra.spec.whatwg.org/#list-iterate) <var>declaration</var> in <var>declarations</var> after <var>target declaration</var>:
>
>         1.  <a id="ref-for-iteration-continue"></a>
>
>             <a id="ref-for-logical-property-group②"></a>
>
>             <a id="ref-for-css-declaration-property-name①①"></a>
>
>             If <var>declaration</var>’s [property name](#css-declaration-property-name) is not in the same [logical property group](https://www.w3.org/TR/css-logical-1/#logical-property-group) as <var>property</var>, then [continue](https://infra.spec.whatwg.org/#iteration-continue).
>
>         2.  <a id="ref-for-iteration-continue①"></a>
>
>             <a id="ref-for-mapping-logic②"></a>
>
>             <a id="ref-for-css-declaration-property-name①②"></a>
>
>             If <var>declaration</var>’ [property name](#css-declaration-property-name) has the same [mapping logic](https://www.w3.org/TR/css-logical-1/#mapping-logic) as <var>property</var>, then [continue](https://infra.spec.whatwg.org/#iteration-continue).
>
>         3.  Let <var>needs append</var> be true.
>
>         4.  <a id="ref-for-iteration-break"></a>
>
>             [Break](https://infra.spec.whatwg.org/#iteration-break).
>
>     4.  If <var>needs append</var> is false, then:
>         1.  Let <var>needs update</var> be false.
>
>         2.  <a id="ref-for-css-declaration-value"></a>
>
>             If <var>target declaration</var>’s [value](#css-declaration-value) is not equal to <var>component
        value list</var>, then let <var>needs update</var> be true.
>
>         3.  <a id="ref-for-css-declaration-important-flag⑥"></a>
>
>             If <var>target declaration</var>’s [important flag](#css-declaration-important-flag) is not equal to whether <i>important</i> flag is set, then let <var>needs update</var> be true.
>
>         4.  If <var>needs update</var> is false, then return false.
>
>         5.  <a id="ref-for-css-declaration-value①"></a>
>
>             Set <var>target declaration</var>’s [value](#css-declaration-value) to <var>component value list</var>.
>
>         6.  <a id="ref-for-css-declaration-important-flag⑦"></a>
>
>             If <i>important</i> flag is set, then set <var>target declaration</var>’s [important flag](#css-declaration-important-flag), otherwise unset it.
>
>         7.  Return true.
>
>     5.  Otherwise, remove <var>target declaration</var> from <var>declarations</var>.
>
> 2.  <a id="ref-for-css-declaration-important-flag⑧"></a>
>
>     <a id="ref-for-css-declaration-value②"></a>
>
>     <a id="ref-for-css-declaration-property-name①③"></a>
>
>     <a id="ref-for-css-declaration②②"></a>
>
>     Append a new [CSS declaration](#css-declaration) with [property name](#css-declaration-property-name) <var>property</var>, [value](#css-declaration-value) <var>component value list</var>, and [important flag](#css-declaration-important-flag) set if <i>important</i> flag is set to <var>declarations</var>.
>
> 3.  Return true.

The <a id="dom-cssstyledeclaration-removeproperty"></a><code>removeProperty(<var>property</var>)</code> method must run these steps:

1.  <a id="ref-for-nomodificationallowederror②"></a>

The <a id="css-property-to-idl-attribute"></a>CSS property to IDL attribute algorithm for <var>property</var>, optionally with a <i>lowercase first</i> flag set, is as follows:

1.  Let <var>output</var> be the empty string.
2.  Let <var>uppercase next</var> be unset.
3.  If the <i>lowercase first</i> flag is set, remove the first character from <var>property</var>.
4.  For each character <var>c</var> in <var>property</var>:
    1.  If <var>c</var> is "`-`" (U+002D), let <var>uppercase next</var> be set.

    2.  <a id="ref-for-ascii-uppercase"></a>

        Otherwise, if <var>uppercase next</var> is set, let <var>uppercase next</var> be unset and append <var>c</var> [converted to ASCII uppercase](https://infra.spec.whatwg.org/#ascii-uppercase) to <var>output</var>.

    3.  Otherwise, append <var>c</var> to <var>output</var>.
5.  Return <var>output</var>.

The <a id="idl-attribute-to-css-property"></a>IDL attribute to CSS property algorithm for <var>attribute</var>, optionally with a <i>dash prefix</i> flag set, is as follows:

1.  Let <var>output</var> be the empty string.
2.  If the <i>dash prefix</i> flag is set, append "`-`" (U+002D) to <var>output</var>.
3.  For each character <var>c</var> in <var>attribute</var>:
    1.  <a id="ref-for-ascii-lowercase⑥"></a>

        If <var>c</var> is in the range U+0041 to U+005A (ASCII uppercase), append "`-`" (U+002D) followed by <var>c</var> [converted to ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase) to <var>output</var>.

    2.  Otherwise, append <var>c</var> to <var>output</var>.
4.  Return <var>output</var>.

### <a id="css-values"></a>6.7. CSS Values

#### <a id="parsing-css-values"></a>6.7.1. Parsing CSS Values

To <a id="parse-a-css-value"></a>parse a CSS value <var>value</var> for a given <var>property</var> means to follow these steps:

1.  <a id="ref-for-parse-a-list-of-component-values"></a>

    Let <var>list</var> be the value returned by invoking [parse a list of component values](https://www.w3.org/TR/css-syntax-3/#parse-a-list-of-component-values) from <var>value</var>.

2.  Match <var>list</var> against the grammar for the property <var>property</var> in the CSS specification.

3.  If the above step failed, return null.

4.  Return <var>list</var>.

<a id="ref-for-parse-a-css-value①"></a>

> <strong data-conversion-semantic="note">Note</strong>
>
> Note: "`!important`" declarations are not part of the property value space and will therefore cause [parse a CSS value](#parse-a-css-value) to return null.

#### <a id="serializing-css-values"></a>6.7.2. Serializing CSS Values

<a id="ref-for-css-declaration②⑦"></a>

To <a id="serialize-a-css-value"></a>serialize a CSS value of a [CSS declaration](#css-declaration) <var>declaration</var> or a list of longhand <a id="ref-for-css-declaration②⑧"></a>CSS declarations <var>list</var>, follow these rules:

1.  <a id="ref-for-list"></a>

    If this algorithm is invoked with a [list](https://infra.spec.whatwg.org/#list) <var>list</var>:

    1.  <a id="ref-for-concept-shorthands-preferred-order①"></a>

        Let <var>shorthand</var> be the first shorthand property, in [preferred order](#concept-shorthands-preferred-order), that exactly maps to all of the longhand properties in <var>list</var>.

    2.  If there is no such shorthand or <var>shorthand</var> cannot exactly represent the values of all the properties in <var>list</var>, return the empty string.

    3.  <a id="ref-for-serialize-a-css-value④"></a>

        Otherwise, [serialize a CSS value](#serialize-a-css-value) from a hypothetical declaration of the property <var>shorthand</var> with its value representing the combined values of the declarations in <var>list</var>.

2.  <a id="ref-for-list①"></a>

    <a id="ref-for-css-parse-something-according-to-a-css-grammar"></a>

    Represent the value of the <var>declaration</var> as a [list](https://infra.spec.whatwg.org/#list) of CSS component values <var>components</var> that, when [parsed](https://www.w3.org/TR/css-syntax-3/#css-parse-something-according-to-a-css-grammar) according to the property’s grammar, would represent that value. Additionally:

    - <a id="ref-for-comb-any"></a>

      If certain component values can appear in any order without changing the meaning of the value (a pattern typically represented by a double bar [\|\|](https://www.w3.org/TR/css-values-4/#comb-any) in the value syntax), reorder the component values to use the canonical order of component values as given in the property definition table.

    - If component values can be omitted or replaced with a shorter representation without changing the meaning of the value, omit/replace them.

    - If either of the above syntactic translations would be less backwards-compatible, do not perform them.

    > <strong data-conversion-semantic="note">Note</strong>
    >
    > Note: The rules described here outlines the <em>general principles</em> of serialization. For legacy reasons, some properties serialize in a different manner, which is intentionally undefined here due to lack of resources. Please consult your local reverse-engineer for details.

3.  <a id="ref-for-typedef-whitespace-token"></a>

    Remove any [\<whitespace-token\>](https://www.w3.org/TR/css-syntax-3/#typedef-whitespace-token)s from <var>components</var>.

4.  <a id="ref-for-serialize-a-css-component-value"></a>

    Replace each component value in <var>components</var> with the result of invoking [serialize a CSS component value](#serialize-a-css-component-value).

5.  Join the items of <var>components</var> into a single string, inserting " " (U+0020 SPACE) between each pair of items unless the second item is a "," (U+002C COMMA) Return the result.

    If <var>elt</var> is [connected](https://dom.spec.whatwg.org/#connected), part of the [flat tree](https://drafts.csswg.org/css-scoping-1/#flat-tree), and its [shadow-including root](https://dom.spec.whatwg.org/#concept-shadow-including-root) has a [browsing context](https://html.spec.whatwg.org/multipage/browsers.html#browsing-context) which either doesn’t have a [browsing context container](https://html.spec.whatwg.org/multipage/browsers.html#browsing-context-container), or whose <a id="ref-for-browsing-context-container①"></a>browsing context container is [being rendered](https://html.spec.whatwg.org/multipage/rendering.html#being-rendered), set <var>decls</var> to a list of all longhand properties that are [supported CSS properties](#supported-css-property), in lexicographical order, with the value being the [resolved value](#resolved-value) computed for <var>obj</var> using the style rules associated with <var>doc</var>. Additionally, append to <var>decls</var> all the [custom properties](https://www.w3.org/TR/css-variables-1/#custom-property) whose [computed value](https://www.w3.org/TR/css-cascade-5/#computed-value) for <var>obj</var> is not the [guaranteed-invalid value](https://drafts.csswg.org/css-variables-1/#guaranteed-invalid-value).

    <a id="ref-for-propdef-overflow"></a>

    > <strong data-conversion-semantic="issue">Issue</strong>
    >
    > <a id="issue-28428295"></a> There are UAs that handle shorthands, and all UAs handle shorthands that used to be longhands like [overflow](https://www.w3.org/TR/css-overflow-3/#propdef-overflow), see [\#2529](https://github.com/w3c/csswg-drafts/issues/2529).

    > <strong data-conversion-semantic="issue">Issue</strong>
    >
    > <a id="issue-0b704bc1"></a> Order of custom properties is currently undefined, see [\#4947](https://github.com/w3c/csswg-drafts/issues/4947).

    Return a live [CSS declaration block](#css-declaration-block) with the following properties:

## <a id="change-history"></a>11. Change History

This section documents some of the changes between publications of this specification. This section is not exhaustive. Bug fixes and editorial changes are generally not listed.

### <a id="changes-from-17-march-2016"></a>11.1. Changes From 17 March 2016

- <a id="ref-for-resolution-value①"></a>

  Serialization of [\<resolution\>](https://www.w3.org/TR/css-values-4/#resolution-value) is changed.

- `[CEReactions]` IDL extended attributes are added.

- Resolved value for logical properties are added.

- <a id="ref-for-propdef-display②"></a>

  <a id="ref-for-valdef-display-contents②"></a>

  `getComputedStyle` for [display](https://www.w3.org/TR/css-display-3/#propdef-display): [contents](https://www.w3.org/TR/css-display-3/#valdef-display-contents) is changed.

- `MediaList.item` now returns serialization.

- `MediaList.item` does not serialize shorthand if importance differs.

- Other specifications are allowed to specify resolved value.

- `index` argument in `insertRule` is now optional.

- `href` attribute of `Stylesheet` and `CSSImportRule` now uses `USVString`.

- `CSSOMString` is introduced.

- Serialization of `CSSMediaRule` and `CSSFontFaceRule` is added.

- <a id="ref-for-cssstyledeclaration-updating-flag③"></a>

  [Updating flag](#cssstyledeclaration-updating-flag) is added to CSS declaration block to avoid serialize-and-reparse on style attribute.

- Serialization of a declaration value is now properly defined.

- `getComputedStyle` now returns the style rules of the node’s document.

- <a id="ref-for-exceptiondef-typeerror①"></a>

  <a id="ref-for-selectordef-slotted①"></a>

  A <code><a href="https://heycam.github.io/webidl/#exceptiondef-typeerror">TypeError</a></code> is thrown when the pseudo-element passed to `getComputedStyle` is unknown or [::slotted()](https://drafts.csswg.org/css-scoping-1/#selectordef-slotted).

- <a id="ref-for-namespacedef-css①"></a>

  <code><a href="#namespacedef-css">CSS</a></code> is switched from interface to namespace.

- <a id="ref-for-cssstyledeclaration⑨"></a>

  `setPropertyValue` and `setPropertyPriority` are removed from <code><a href="#cssstyledeclaration">CSSStyleDeclaration</a></code> due to lack of interest from implementations.

- <a id="ref-for-document④"></a>

  <a id="ref-for-documentorshadowroot⑧"></a>

  The `styleSheets` IDL attribute is moved from <code><a href="https://dom.spec.whatwg.org/#document">Document</a></code> to <code><a href="https://dom.spec.whatwg.org/#documentorshadowroot">DocumentOrShadowRoot</a></code>.

- LinkStyle.sheet now returns `CSSStyleSheet` instead of `StyleSheet`

- Deprecated CSSStyleSheet members are defined.

- The `CSSRule.type` attribute is deprecated.

- <a id="ref-for-ratio-value①"></a>

  Serialization of [\<ratio\>](https://www.w3.org/TR/css-values-4/#ratio-value) is added.

- `CSSStyleDeclaration.cssText` now returns the empty string for computed style.

- <a id="ref-for-custom-property⑥"></a>

  [Custom properties](https://www.w3.org/TR/css-variables-1/#custom-property) are included in `getComputedStyle`.

- MathML IDL is introduced.

- <a id="ref-for-csskeyframesrule②"></a>

  <a id="ref-for-csskeyframerule②"></a>

  Serialization of <code><a href="https://www.w3.org/TR/css-animations-1/#csskeyframesrule">CSSKeyframesRule</a></code> and <code><a href="https://www.w3.org/TR/css-animations-1/#csskeyframerule">CSSKeyframeRule</a></code> is added.

- Serialization of media query is changed.

- A shorthand is not serialized if there are longhands with other property group / mapping logic in between the longhands of that shorthand.

- <a id="ref-for-cssstylerule③"></a>

  <code><a href="#cssstylerule">CSSStyleRule</a></code> serialization is aware of nesting now.

- Constructable stylesheets is introduced.

## <a id="w3c-conformance"></a> Conformance

### <a id="w3c-conventions"></a> Document conventions

Conformance requirements are expressed with a combination of descriptive assertions and RFC 2119 terminology. The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, and “OPTIONAL” in the normative parts of this document are to be interpreted as described in RFC 2119. However, for readability, these words do not appear in all uppercase letters in this specification.

All of the text of this specification is normative except sections explicitly marked as non-normative, examples, and notes. [\[RFC2119\]](#biblio-rfc2119)

Examples in this specification are introduced with the words “for example” or are set apart from the normative text with `class="example"`, like this:

> <strong data-conversion-semantic="example">Example</strong>
>
> <a id="w3c-example"></a>
>
> This is an example of an informative example.

Informative notes begin with the word “Note” and are set apart from the normative text with `class="note"`, like this:

> <strong data-conversion-semantic="note">Note</strong>
>
> Note, this is an informative note.

Advisements are normative sections styled to evoke special attention and are set apart from other normative text with `<strong class="advisement">`, like this: <strong data-conversion-semantic="advisement">Advisement:</strong> <strong> UAs MUST provide an accessible alternative. </strong>

### <a id="w3c-conformance-classes"></a> Conformance classes

Conformance to this specification is defined for three conformance classes:

style sheet  
A [CSS style sheet](https://www.w3.org/TR/CSS21/conform.html#style-sheet).

renderer  
A [UA](https://www.w3.org/TR/CSS21/conform.html#user-agent) that interprets the semantics of a style sheet and renders documents that use them.

authoring tool  
A [UA](https://www.w3.org/TR/CSS21/conform.html#user-agent) that writes a style sheet.

A style sheet is conformant to this specification if all of its statements that use syntax defined in this module are valid according to the generic CSS grammar and the individual grammars of each feature defined in this module.

A renderer is conformant to this specification if, in addition to interpreting the style sheet as defined by the appropriate specifications, it supports all the features defined by this specification by parsing them correctly and rendering the document accordingly. However, the inability of a UA to correctly render a document due to limitations of the device does not make the UA non-conformant. (For example, a UA is not required to render color on a monochrome monitor.)

An authoring tool is conformant to this specification if it writes style sheets that are syntactically correct according to the generic CSS grammar and the individual grammars of each feature in this module, and meet all other conformance requirements of style sheets as described in this module.

### <a id="w3c-partial"></a> Partial implementations

So that authors can exploit the forward-compatible parsing rules to assign fallback values, CSS renderers <strong>must</strong> treat as invalid (and [ignore as appropriate](https://www.w3.org/TR/CSS21/conform.html#ignore)) any at-rules, properties, property values, keywords, and other syntactic constructs for which they have no usable level of support. In particular, user agents <strong>must not</strong> selectively ignore unsupported component values and honor supported values in a single multi-value property declaration: if any value is considered invalid (as unsupported values must be), CSS requires that the entire declaration be ignored.

#### <a id="w3c-conform-future-proofing"></a> Implementations of Unstable and Proprietary Features

To avoid clashes with future stable CSS features, the CSSWG recommends [following best practices](https://www.w3.org/TR/CSS/#future-proofing) for the implementation of [unstable](https://www.w3.org/TR/CSS/#unstable) features and [proprietary extensions](https://www.w3.org/TR/CSS/#proprietary-extension) to CSS.

### <a id="w3c-testing"></a> Non-experimental implementations

Once a specification reaches the Candidate Recommendation stage, non-experimental implementations are possible, and implementors should release an unprefixed implementation of any CR-level feature they can demonstrate to be correctly implemented according to spec.

To establish and maintain the interoperability of CSS across implementations, the CSS Working Group requests that non-experimental CSS renderers submit an implementation report (and, if necessary, the testcases used for that implementation report) to the W3C before releasing an unprefixed implementation of any CSS features. Testcases submitted to W3C are subject to review and correction by the CSS Working Group.

Further information on submitting testcases and implementation reports can be found from on the CSS Working Group’s website at [https&#x3A;&#x2F;&#x2F;www&#x2E;w3&#x2E;org&#x2F;Style&#x2F;CSS&#x2F;Test&#x2F;](https://www.w3.org/Style/CSS/Test/)&#x2E; Questions should be directed to the [public-css-testsuite@w3.org](https://lists.w3.org/Archives/Public/public-css-testsuite) mailing list.
