# CSSOM property reflections

This root-owned offline tool generates ordinary property getter/setter pairs for
`surgeist-cssom::CssStyleProperties` and read-only getters for its owning captures.
The production crate consumes checked-in Rust; it never runs this tool at build
time and does not depend on the generator.
The selected [CSSStyleProperties interface](../../references/cssom-1--editor-capture-20261009--d42e145ec395.md#cssstyleproperties)
defines the reflection domain; CSS metadata establishes the available authored
spellings and grammar owners.

The inventory comes from public CSS metadata:
`CssKnownProperty::all`, `canonical_name`, `aliases`, `legacy_shorthands`, and
`CssSvgGlyphOrientationVerticalDeclaration::metadata`. The independent SVG
declaration and finite legacy shorthand share an authored spelling while keeping
their different grammar provenance. Each authored spelling gets one Rust pair;
JavaScript alternate spellings do not add Rust aliases. Custom properties stay
with the string-based declaration API.

Regenerate from the repository root:

```sh
cargo run --offline --locked -j 1 -p surgeist-cssom-reflections
```

The generated [source](../../crates/surgeist-cssom/src/generated_property_reflections.rs)
records each CSS spelling and its public metadata origin. Its private
[delegation macro](../../crates/surgeist-cssom/src/property_reflections.rs) calls
the owning common declaration query/setter with empty priority. Known grammar
membership supplies methods; the caller's composed support profile still decides
usable values, so a generated method does not promise renderer support.

Dashed names become snake_case. Exactly one leading vendor hyphen is removed.
Rust keywords use raw identifiers; forbidden raw names (`self`, `Self`, `super`,
`crate`) and structural-member collisions use a documented `_property` suffix.
`float` keeps its explicit standard `css_float` reflection. Unresolved getter or
setter collisions fail generation instead of dropping a property.

Refresh the owning API artifact after source changes, then check reproducibility
and the actual live/captured public method inventories:

```sh
CARGO_BUILD_JOBS=1 CARGO_NET_OFFLINE=true cargo run --offline -j 1 --manifest-path api/generator/Cargo.toml -- --crate surgeist-cssom
cargo run --offline --locked -j 1 -p surgeist-cssom-reflections -- --check
cargo test --offline --locked -j 1 -p surgeist-cssom-reflections
```

Check mode compares exact generated bytes and the audited API's method names
against the explicit structural inventories plus generated reflections. A new
structural method requires deliberate collision reconciliation. This reads the
root-owned generated API artifact; it does not parse handwritten Rust or turn the
API auditor into a source generator. See the [root audit guide](../../docs/how-to.md#check-public-api-audits)
for the separate artifact freshness check.
